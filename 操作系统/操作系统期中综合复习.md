## 三、判断题：给出结论，再补一句理由

先遮住右栏。旧卷常要求错题说明理由；最简洁的写法是说清**哪一个事件**或**哪一种执行顺序**能推翻题干。

| 判断 | 答案与理由 |
|---|---|
| ① 应用每调用一次 printf，就立即执行一次 write。 | **错。** printf 可先写入用户态缓冲。刷新时才可能调用 write，多次输出也可能合并。 |
| ② 从用户态进入内核态，就一定发生了进程切换。 | **错。** 同一线程可以进入内核处理系统调用，再返回原线程。进程切换还涉及更换执行现场。 |
| ③ 等待 I/O 的进程，只要 I/O 完成就会立刻运行。 | **错。** 完成事件使它由等待变就绪，之后须被调度才运行。 |
| ④ 同一进程的线程各有栈，因此其他线程绝对不能访问这块栈。 | **错。** 各线程分别使用自己的栈，但共享地址空间。把一个仍有效的栈对象地址传给另一线程，后者可能访问它。 |
| ⑤ fork 后，普通变量与继承的文件偏移都由父子分别维护。 | **错。** 普通变量后续各自修改；继承的文件描述符可指向同一个内核打开文件描述，从而共享偏移。 |
| ⑥ RR 中把时间片缩短，总能同时提高响应速度和系统效率。 | **错。** 短时间片通常让就绪任务更早获得一次 CPU，也可能增加切换开销。片尾只有自己就绪时甚至无需换人。 |
| ⑦ 同时到达、CPU 长度已知且忽略开销时，非抢占 SJF 可使平均等待最短。 | **对。** 相邻长任务 a 在短任务 b 前时，交换顺序可让两者等待总和减少 a−b，后面任务的开始时刻不变。 |
| ⑧ 在一颗 CPU 上关中断，就能保证多核系统的共享计数器互斥更新。 | **错。** CPU0 关掉本地中断时，CPU1 仍能访问该计数器。 |
| ⑨ 两次分别原子的操作“读 count、写回旧值加一”合起来必然是原子加一。 | **错。** 两线程都可先读到 5，再分别写回 6。要用原子读改写，或用同一把锁覆盖完整更新。 |
| ⑩ 有了保护缓冲区的 mutex，生产者与消费者就不再需要条件同步。 | **错。** 拿到锁的消费者仍可能面对空缓冲区；互斥只能限制同时访问者，空位与产品的到达还要单独协调。 |
| ⑪ 对信号量先 V 后 P 可以留下许可；无人等待时对条件变量 signal 不会留下通知。 | **对。** 信号量记录许可。条件变量配合共享状态使用，后来者应持锁检查状态。 |
| ⑫ 哲学家方案消除了死锁，就自动保证每人有限等待。 | **错。** 系统可以始终有人进餐，但同一哲学家反复被邻居抢先，这属于饥饿。 |

## 四、选择题：先认清题干里的对象

| 容易混的选项 | 选择依据 |
|---|---|
| Shell / API / 系统调用 | Shell 解释用户命令；库 API 是程序调用的接口，可能直接在用户态完成；系统调用是请求内核服务的受控入口。微内核中的用户态服务通常经**消息传递**协作。 |
| 程序 / 进程 / 线程 / 管程 | 程序是指令集合；进程是程序的一次执行，拥有地址空间和资源；线程是执行流，内核线程通常是调度单位；管程封装共享数据和同步规则。 |
| text / data、BSS / heap / stack | 指令在 text；普通已初始化静态对象通常在 data，零初始化或未显式初始化的静态对象通常在 BSS；动态分配对象在堆，调用帧通常在栈。 |
| 共享内存 / 管道 / Socket / RPC | 共享内存映射同一组页，要自管同步；管道是字节流；Socket 是通信端点；RPC 封装远程调用。RPC 超时可能是回复丢失，直接重试非幂等操作可能重复执行。 |
| 等待 / 响应 / 周转 | “首次获得 CPU”找响应；“在就绪队列总共多久”找等待；“到达至完成”找周转。HRRN 的响应比为 (等待+服务)/服务。 |
| FCFS / SJF / SRTF / RR / MLFQ | 护航效应找 FCFS；按下一段 CPU 长度选找 SJF；按剩余时间抢占找 SRTF；尾部重排找 RR；根据行为升降队列找 MLFQ。 |
| mutex / 计数信号量 / 条件变量 | 保护一组字段用锁；限制并发名额用计数信号量；等待受锁保护的状态成立用条件变量。互斥量有持有者，信号量可由不同线程 P、V。 |
| TAS / CAS / 内存顺序 | TAS 取旧值并置位；CAS 比较预期值，相符才更新。原子性约束一次操作能否拆开，release/acquire 约束跨线程可见的读写顺序。 |

**三个常见计算选项**

- **Amdahl（L4 第 13–16、64 页）。** 固定工作量、串行占比 s、N 核理想加速比为 `1/[s+(1−s)/N]`。串行 20%、4 核为 **2.5 倍**，核数趋于无穷时上限为 **5 倍**。创建线程、同步和内存竞争都会影响实际结果。
- **预测 CPU 区间（L5 第 24–26 页）。** `下次预测 = α×本次实际 + (1−α)×原预测`。α=0.5、实际 6、原预测 10，则新预测是 8。
- **实时与排队（L5 第 53–56、69–70 页）。** RM 按周期短者优先，EDF 按当前作业的绝对截止时间早者优先。独立、可抢占、无开销、单 CPU 且截止期等于周期时，EDF 判据是 Σ(Cᵢ/Tᵢ)≤1；RM 的充分界是 n(2^(1/n)−1)。Little 定律 `Lq=λWq`，稳定系统平均排队 14 个、每秒到达 7 个，平均排队 **2 秒**。

## 五、简答题：把机制和例子连起来

**1．描述一次 read 系统调用，并说明为什么要检查参数。（L2）** 应用经库准备调用号、文件描述符、缓冲区和长度，通过受控入口进入内核。内核分派到相应处理函数，检查 fd 是否有效、是否可读、缓冲区是否可写及长度是否合法，再执行或等待 I/O。返回正数是实际读到的字节数，请求长度大于零的普通文件读取返回 0 表示 EOF，失败时返回错误。复制文件时，只处理实际读到的字节；遇到短写应从尚未写出的部分继续。

**2．什么是机制与策略？模块化 Linux 为什么仍可归为单体内核？（L2）** 机制提供“如何完成”的手段，例如时钟中断、保存和恢复寄存器；策略决定“该选谁”，例如 RR、优先级调度。判断内核结构看服务在哪个地址空间运行：Linux 可加载模块仍能在内核空间运行；微内核则把更多服务放在用户态，依靠基本 IPC 等内核机制协作，隔离较强但增加通信成本。

**3．写全三态之间的转换，说明 PCB 的作用。（L3）** 就绪→运行：被选中并分派 CPU；运行→就绪：时间片用完或被抢占；运行→等待：申请尚不能满足的 I/O 或事件；等待→就绪：事件发生。PCB 保存标识与状态、PC 和寄存器、调度、地址空间及资源信息，内核据此管理并恢复进程。上下文切换还可能付出缓存或 TLB 成本。

**4．进程与线程、并发与并行各有什么区别？（L3–4）** 进程提供资源与隔离边界，同进程线程共享代码、堆、全局变量、文件表，各有 PC、寄存器、栈及 TLS。单核交替推进多个任务就有并发；同一时刻在多个执行单元上工作才有并行。多对一模型的多个用户线程映射到同一内核线程，一个阻塞系统调用可能拖住整组；一对一模型下，其他就绪线程仍可获得 CPU。

**5．比较 FCFS、MLQ 和 MLFQ，用 30 ms 的长任务举例。（L5）** FCFS 按就绪顺序服务，长任务在队首会拖慢短任务。MLQ 按固定类别入队。MLFQ 根据已消耗的 CPU 配额等反馈调整队列。按课件的三级例子，Q0 用 RR 8 ms，Q1 用 RR 16 ms，Q2 用 FCFS。一个无竞争且不阻塞的 30 ms 任务依次运行 **8、16、6 ms**。新交互任务可在高队列更早运行；低队列长期得不到机会时可用优先级提升缓解饥饿。

**6．临界区的三个要求是什么？严格轮换为什么不合格？（L6）** 互斥要求同一时刻最多一人进入；前进要求临界区空闲且有人申请时，选择不能无限推迟；有限等待要求一个申请者被别人先行的次数有上界。严格轮换能保证互斥，但若轮到 P1 而 P1 根本不想进，想进的 P0 也会被挡住，违反前进。Peterson 让 Pi 声明 flag[i]，再置 turn=j，只在对方也申请且轮到对方时等待；经典证明假定两进程及顺序一致的原子读写。

**7．区分同步、互斥、进程、管程。（L3、L6–7）** 同步约束先后，例如产品产生后才取；互斥约束同时访问数，例如同一时刻最多一人修改队列下标。进程是活动的执行实体；管程将共享数据、访问过程、互斥和条件等待封装起来。生产进程和消费进程可以调用同一缓冲区管程；取产品的调用者发现为空时应等待并让出管程，否则生产者无法进入使条件成立。

**8．如何区别死锁与饥饿？用读者优先举例。（L6–7）** 死锁中一组执行者相互等待，都无法推进。饥饿中某个执行者长期得不到资源，别人仍可前进。读者优先方案允许多个读者同时访问，第一个读者申请共享资源，最后一个释放；读者计数由单独的互斥机制保护。只要新读者持续在老读者离开前加入，计数始终大于零，写者就可能饥饿。

**第二遍再过的章末小问**

- **L2**　同一 CPU 仍可能因为可执行格式、ABI 或库不兼容而无法运行同一程序。链接器解析符号和重定位，装载器建立进程映像。开机一般经过固件、引导、内核初始化、用户空间首进程和服务，最后提供登录环境。
- **L3**　空管道仍有任一写端开着，阻塞读会继续等；数据已读完且所有写端关闭，才返回 0。共享内存让进程映射同一数据，读写顺序另由锁或信号量保障。
- **L4**　线程池复用工作线程，TLS 可能留下上个任务的值。join 等待目标结束，无法保护执行中的共享写入。取消请求成功后，目标可能到取消点才退出。OpenMP 的 reduction 可各自累加再合并，critical 让同名临界区互斥执行。
- **L5**　多核迁移可均衡负载，也可能损害缓存或 NUMA 本地性。普通 Linux 任务 nice 值越小权重越高；实时优先级的用户数值通常越大越高。公平调度的虚拟截止时间与实时任务的实际截止时间含义不同。
- **L6**　自旋适合临界区短且持锁者能继续运行的情况；等待较长时可阻塞并让出 CPU。朴素 CAS 自旋锁能互斥，仍可能插队。写者先写数据再 release 发布标志，读者用 acquire 读到此次发布的值，才能据此观察之前的数据。
- **L7**　POSIX 无名信号量要跨进程使用，需设置相应 pshared 且把对象放入共享内存。Java 的 wait 释放相应对象锁，notifyAll 后等待者还得重新竞争锁；没成功 acquire 的线程不能替自己 release 一个许可。

## 六、应用题：四类题的纸笔解法

<a id="gantt"></a>

### 1．给一组进程，画甘特图并逐个算时间

设 A 为到达时刻，S 为首次运行时刻，C 为完成时刻，B 为 CPU 执行总时长。**周转 = C−A，响应 = S−A，等待 = 各段就绪排队之和。** 只有运行和就绪排队时，等待可简算为 C−A−B；若题目还有 I/O 阻塞，要另扣阻塞时间。

**2019、2023 真题。** P1、P2、P3、P4 按此顺序在时刻 0 就绪，CPU 时间为 (9,2,3,2) ms，优先级为 (3,1,2,4)。本次演算取小数字优先、同长按队列顺序、RR 时间片 q=1 ms，忽略切换开销。先只看题干，画完再对。

| 算法 | 甘特图，数字为时刻 | 等待时间，始终按 P1–P4 填 | 平均等待 |
|---|---|---|---|
| FCFS | `0 P1 9 P2 11 P3 14 P4 16` | 0，9，11，14 | 8.5 ms |
| 非抢占 SJF | `0 P2 2 P4 4 P3 7 P1 16` | 7，0，4，2 | **3.25 ms** |
| 非抢占优先级 | `0 P2 2 P3 5 P1 14 P4 16` | 5，0，2，14 | 5.25 ms |
| RR | `0 P1 1 P2 2 P3 3 P4 4 P1 5 P2 6 P3 7 P4 8 P1 9 P3 10 P1 16` | 7，4，7，6 | **6 ms** |

**检查 RR 的一格。** P1 首次在 0 运行，完成于 16，共执行 9 ms，因此响应是 0，等待是 7。2019 答案表这一格写成了 6；按 q=1 重算，四人平均是 (7+4+7+6)/4=6 ms。最后 10–16 只有 P1 就绪，可把连续时间片画成一段。

**换个条件再练。**

- **改问周转，2018 原题。** A–E 同时到达，运行时间 (10,6,2,4,8)，优先级 (3,5,2,1,4)，这次是**大数字优先**。FCFS 完成时刻 (10,16,18,22,30)，平均周转 19.2 ms；优先级顺序 B、E、A、C、D，平均 20 ms；RR 取 q=2，按 A–E 的完成时刻为 (30,22,6,16,28)，平均 20.4 ms。
- **改为分批到达，L5 第 23 页。** 到达 (0,1,2,3)，长度 (8,4,9,5)。SRTF 在时刻 1 比较 P1 剩余 7 与 P2 所需 4，选 P2；时刻 2、3 新到者均更长。得到 `0 P1 1 P2 5 P4 10 P1 17 P3 26`，等待 (9,0,15,2)，平均 6.5。单 CPU、已知长度、忽略开销时，SRTF 优化的是平均周转，在单 CPU 区间模型中也优化平均等待；“首次响应”仍按 S−A 算。
- **课件独立练习，L5 第 36 页。** P1–P5 同时到达，长度 (2,1,8,4,5)，优先级 (2,1,4,2,3)，大数字优先、同级按编号，q=2。四个平均等待的核对值为 FCFS 6.2、非抢占 SJF 4.6、非抢占优先级 11、RR 7.2 ms。

### 2．有界缓冲区：从 P/V 改成条件变量

**2019、2023 原题。** 单槽初始为空，多个生产者与消费者反复操作。先把三种职责写在草稿上：mutex 保护缓冲区和下标；empty 记录空位；full 记录可取产品。以下容量记为 N，原题代 **N=1**。

```text
初始：empty = N，full = 0，mutex = 1

生产者循环                          消费者循环
    在锁外生产 item                     P(full)
    P(empty)                            P(mutex)
    P(mutex)                            item = 取出一个产品
    放入 item                           V(mutex)
    V(mutex)                            V(empty)
    V(full)                             在锁外消费 item
```

**为什么先 P 资源再 P 锁？** 设缓冲区已满：若生产者先拿 mutex 再等 empty，它会持锁等空位；消费者又必须拿这把锁才能取出产品。二者互等。反过来看，消费者取走后腾出的是空位，故最后写 **V(empty)**；2023 扫描卷的学生答案在这里写成 V(full)。

**售票厅变式（2018）。** 可同时容纳 20 人，只需一个初值为 20 的计数信号量。每位购票者执行 `P(seats) → 进厅 → 买票 → 离厅 → V(seats)`。按 L6 先减后判的记录型实现，若 26 人都先申请而尚无人归还，seats=−6，表示等待**这个信号量**的有 6 人。S>0 表示还有许可，S=0 表示无余量且无人排队。

**厨师与服务员变式（L7 第 54–55 页）。** 单传菜位，布尔量 full 初值为 false，由 mutex 保护；not_empty、not_full 是条件变量。和上面的信号量版本相比，这里的 full 只是状态标志。

```text
厨师                                  服务员
lock(mutex)                           lock(mutex)
while (full)                          while (!full)
    wait(not_full, mutex)                 wait(not_empty, mutex)
放菜，full = true                      取菜，full = false
signal(not_empty)                     signal(not_full)
unlock(mutex)                         unlock(mutex)
```

**这段代码最可能的追问。** 服务员先来，wait 原子地释放锁并进入等待；厨师拿锁放菜、改状态、通知。POSIX 下通知时厨师仍持锁，服务员要重新取得同一把锁才从 wait 返回。返回后用 while 重查，因为状态可能在重新得锁前被另一服务员改变，也可能发生虚假唤醒。L6 第 50–55 页另示范“唤醒并等待”的教材管程：通知者暂停，被唤醒者先执行。写答案时看题目指定的是哪种语义。

### 3．fork、线程和文件偏移：先数 open，再看退出

**2020 原题的共同条件。** 文件初始为空，不用追加模式，调用成功，每次 write 写一个字节，调度先后未知。每段程序独立运行。

| 程序结构 | 文件最后可能是 | 推理 |
|---|---|---|
| 先 fork。子进程单独 open 后写 a，父进程也单独 open 后写 b。 | `a` 或 `b` | 两次独立 open 都从偏移 0 写。后写的一方覆盖先写的字节。 |
| 先 open 一次，再 fork。子把普通变量改为 a，父改为 b，各向继承的 fd 写自己的字节。 | `ab` 或 `ba` | 两个地址空间各有变量，继承的 fd 共享同一打开文件描述和偏移。先写在 0，后写在 1。 |
| 主线程 open，创建工作线程写 a，主线程自己写 b 后直接从 main 返回，未 join。 | `b`、`ab` 或 `ba` | 主线程退出进程前一定写过 b。若工作线程来不及执行，只有 b；若两次写都完成，就按先后排列。 |

**再改一行。** 第三段若把 join 放在写 b 前，工作线程必须已结束，结果只有 ab；放在写 b 后、main 返回前，两次写都完成，仍可能 ab 或 ba。另一个常见问法是 L3 第 27 页的 fork/exec/wait：fork 后父子都从返回点继续；子成功 exec 后原代码后续打印不会执行；父对该子进程 waitpid 成功后才执行的打印必在子进程退出之后。

### 4．三把锁：按顺序写出“谁持有、谁等待”

**2020 原题。** a 依序申请 y、z，b 申请 z、x，c 申请 x、y，每人拿到两把才释放。

1. 写出一条能死锁的执行。a 拿 y，b 拿 z，c 拿 x，然后 a 等 z，b 等 x，c 等 y。等待图为 `a → b → c → a`，箭头从等待者指向持有者。
2. 定位临界的一步。在这条序列的前两步后，b 还可以先拿 x 并完成；第三步后，每人都已拿到第一把，谁也无法获得第二把并完成。
3. 判断修改是否有效。改变 unlock 顺序无效，因为程序可在任何一条 unlock 前就卡住。规定 x<y<z，所有线程按编号递增拿自己需要的锁，可破坏循环等待。抢占 CPU 只切换执行者，仍会保留它已经拿到的锁。
4. 换成 L7 的哲学家。五人各拿左筷就会成环；可规定筷子全序，或五人中至多四人同时尝试，或由管程在两根都可用时一次授权。管程版在放下筷子后检查左右邻居，先登记获准者为 EATING 再通知。若还要求人人有限等待，就要再考虑公平性。

## 七、60 分钟闭卷模拟

这是按通知题型编写的自测。**推荐计时**为判断 7 分钟、选择 8 分钟、简答 15 分钟、应用 25 分钟、检查 5 分钟。把答案区遮住，只拿纸和笔作答。

### 判断题（7 分钟）

1. 微内核可以让部分系统服务作为用户态进程运行，并用消息传递与之协作。
2. 父进程关闭了管道写端，子进程的下一次阻塞 read 就一定返回 0。
3. 四核机器上的任意四个用户线程都可以同时运行在四颗核上。
4. 在 RR 中，一个进程的响应时间可以为 0，而总等待时间大于 0。
5. 无人等待时先对 POSIX 条件变量 signal，后来进入 wait 的线程可凭这次 signal 直接通过。
6. 读者优先方案可能既保持共享数据互斥写入，又让某个写者长期等待。

### 选择题（8 分钟，本组均为单选）

1. 哪一项会使阻塞在 I/O 上的进程转为就绪？ A 时间片到期　B I/O 完成　C 创建 PCB　D 执行 exec。
2. 哪一项通常由同进程的线程共享？ A 栈指针　B PC　C 打开文件表　D TLS 实例。
3. 消除朴素 TAS 锁反复被新来者抢先的问题，直接对应临界区哪项要求？ A 互斥　B 有限等待　C 地址隔离　D 内存持久化。
4. 一个固定规模程序有 25% 必须串行，4 核理想加速比最接近？ A 1.33　B 2.29　C 3.20　D 4。
5. 一个周期任务的下一次截止时间变成所有就绪作业中最早，哪种算法直接按此选择？ A FCFS　B RM　C EDF　D HRRN。

### 简答题（15 分钟）

1. 用一次读文件为例，区分库调用、系统调用、模式切换和上下文切换。能否进入内核后仍返回同一线程？
2. 甲先写完共享数据，乙随后才能读。用一个信号量写出初值及两方操作。若改用条件变量，应额外保存什么状态？为什么？
3. 写者已经在等，为什么读者优先系统仍可能让新读者进入？说明第一个读者和最后一个读者各负责哪一步。

### 应用题（25 分钟）

**A．调度。** 单 CPU 上，A、B、C 的到达时刻为 (0,1,2)，运行时长为 (5,3,1)，单位 ms，无 I/O、忽略切换开销。分别用 SRTF 和 RR（q=2）画图，求每个进程的等待、响应及两种平均值。RR 在时刻 2 先把刚到的 C 入队，再把片尾未完成的 A 放到队尾。

**B．同步。** 一个空货架最多放 2 件货，多个补货员和顾客并发操作。① 写出信号量、初值、双方伪代码。② 有人建议顾客先锁货架、再等有货，请构造会卡住的顺序。③ 改为条件变量时，用一句话各说明顾客何时放锁、何时重新得锁以及为什么要重查库存。

### 模拟答案与核对

**判断。** ①对。②错：管道里可能还有数据，或子进程等其他持有者仍开着写端。③错：还取决于用户到内核线程的映射，例如多对一只能由一个内核线程执行。④对：先运行、被抢占再排队即可。⑤错：无人等待时通知不积累。⑥对：只要读者群体一直有人，新来的读者仍可加入。

**选择。** ① B，就绪表示 I/O 已不再阻碍执行。② C，其他三项各线程独立。③ B，有限等待约束单个申请者被他人先行的次数。④ B，1/(0.25+0.75/4)=16/7≈2.29。⑤ C，EDF 看绝对截止时间，RM 看周期。

**简答。**

1. 应用可经库封装请求 read，受控入口带来用户态到内核态的模式切换，内核检查并执行，然后可以返回同一线程。若 I/O 需等待，调度器还可能换到另一线程，此时才涉及不同执行现场的切换。
2. 信号量 done=0；甲写完后 V(done)，乙先 P(done) 再读。甲先发许可也能保存。条件变量版本需要一个由同一把锁保护的 ready 标志；甲改 ready 后通知，乙拿锁后用 while 检查 ready，避免漏掉早先完成的事件或被唤醒时条件仍不成立。
3. 读者组共同持有资源访问权。read_count 从 0 到 1 的第一个读者申请资源，从 1 到 0 的最后一个释放；修改计数本身须互斥。持续新来读者能使计数一直大于 0，所以写者即使先到也可能饥饿。

**应用 A。** 下面每个三元组均按 A、B、C 排列，时间单位 ms。

| 算法 | 甘特图 | 各自等待 / 平均 | 各自响应 / 平均 |
|---|---|---|---|
| SRTF | `0 A 1 B 2 C 3 B 5 A 9` | (4,1,0) / **5/3** | (0,0,0) / **0** |
| RR | `0 A 2 B 4 C 5 A 7 B 8 A 9` | (4,4,2) / **10/3** | (0,1,2) / **1** |

验算 RR 的 B：时刻 1 到达、时刻 2 首次运行、时刻 8 完成，总共用 CPU 3 ms。响应是 2−1=1，等待是 8−1−3=4。两张图长度都应为 5+3+1=9 ms。

**应用 B。** ① 初值 empty=2、full=0、mutex=1。补货员执行 `P(empty) → P(mutex) → 放 → V(mutex) → V(full)`；顾客执行 `P(full) → P(mutex) → 取 → V(mutex) → V(empty)`。② 初始为空，顾客拿锁后等货；补货员有空位却拿不到锁，无法放货。③ 顾客在锁内发现库存为零，在 wait 内原子地释放锁并等待；被通知且重新取得锁后 wait 才返回。货可能已被另一个顾客取走，所以用 while 复查。

**交卷前 5 分钟。** 看清题目求等待、响应还是周转，优先级是大数字还是小数字；检查甘特图每个人的运行段之和；核对消费者最后归还空位、wait 之后重新检查条件；判断题判错时，补上那一句能推翻题干的理由。
