### （二）今年新版课件（Lesson 2–7）高频命题判断清单（24 道核心陷阱）

#### 【Lesson 2–3：系统调用、内核结构、进程与 IPC】
1. **“应用程序每调用一次 `printf()`，就会立即触发一次 `write()` 系统调用。”**
   - **×**。`printf()` 是标准库函数，数据常先写入**用户态缓冲区**，缓冲刷新（满、换行、`fflush` 或退出）时才调用 `write()`，多次输出可能合并为一次系统调用。
2. **“CPU 从用户态切换到内核态，就意味着发生了进程上下文切换。”**
   - **×**。系统调用或中断进入内核只是**模式切换（Mode Switch）**，内核处理完毕后可直接返回原进程继续运行，不一定切换进程。
3. **“Linux 支持动态加载内核模块（`.ko`），因此 Linux 属于微内核操作系统。”**
   - **×**。Linux 是结合了模块化的**单体内核**；加载后的模块直接运行在**内核地址空间**并通过函数调用交互，而非微内核的用户态独立进程 + 消息传递。
4. **“等待 I/O 的进程在 I/O 操作完成后，会立即由等待态直接进入运行态。”**
   - **×**。I/O 完成后进程只能由**等待态转为就绪态**（进入就绪队列），必须经 CPU 调度器选中分派后才能进入运行态。
5. **“`fork()` 之后，父子进程各自的普通全局变量与继承的已打开文件偏移量都彼此独立、互不影响。”**
   - **×**。虚拟地址空间（普通变量）各自独立（写时复制）；但继承的文件描述符指向同一个内核**打开文件描述**，因此**共享文件读写偏移量（file offset）**。
6. **“父进程尚未调用 `wait()`，此时它创建的正在运行的子进程就是僵尸进程；一旦父进程退出，子进程也会自动终止。”**
   - **×**。只有**已终止**但尚未被父进程 `wait` 回收的子进程才是**僵尸进程**；父进程先退出会使子进程成为**孤儿进程**，被 `init`/`systemd`（PID 1）收养并继续运行。
7. **“当匿名管道（pipe）内已经没有数据时，阻塞模式的 `read()` 一定会立即返回 `0`（EOF）。”**
   - **×**。仅当管道已空**且系统中所有指向该管道的写端描述符（含读进程自身继承未关的写端）均已关闭**时才返回 `0`；只要仍有任一写端打开，`read()` 就会阻塞等待。
8. **“客户端发起 RPC 远程过程调用发生超时，可以断定服务端没有执行该请求，直接重试总是安全的。”**
   - **×**。超时可能是响应报文在网络丢失而**服务端实际已执行完毕**；对非幂等操作（如扣款）直接重试会导致重复执行。

#### 【Lesson 4–5：线程模型、并发与 CPU 调度】
9. **“同一进程内的每个线程拥有各自独立的栈，因此一个线程绝对无法读写同进程另一线程栈上的变量。”**
   - **×**。同进程线程**共享同一个虚拟地址空间**，硬件不隔离各线程栈；若将某线程有效栈变量的地址（指针）传给另一线程，后者可以直接访问。
10. **“在多对一（Many-to-One）线程模型中，即使运行在 8 核处理器上，同一进程的多个用户线程也无法并行执行，且任一线程发起阻塞系统调用会阻塞整个进程。”**
    - **√**。（内核只感知那唯一一个内核线程，同一时刻只能在一个核上调度，阻塞即全组停摆。）
11. **“调用 `pthread_cancel(tid)` 成功返回后，说明目标线程已经终止并释放了所有资源。”**
    - **×**。`pthread_cancel` 仅发出取消请求；若目标线程禁用取消或处于默认的**延迟取消（Deferred）**模式，需运行到**取消点**才退出，且需 `pthread_join` 确认回收。
12. **“在线程池中复用工作线程处理请求时，线程局部存储（TLS）变量会在每个新任务开始时自动清空重置。”**
    - **×**。TLS 生命周期随工作线程而非随任务；工作线程复用时 TLS 会保留上一个任务遗留的旧值，新任务必须显式覆盖或清理。
13. **“某任务在时刻 0 到达并立刻获得 CPU，响应时间为 0，说明它的总等待时间也一定为 0。”**
    - **×**。响应时间只看**首次**获得 CPU 的等待；在抢占式调度（如 RR、SRTF）下，该任务后续可能被多次抢占回就绪队列排队，累计总等待时间可以大于 0。
14. **“在时间片轮转（RR）调度中，每当定时器时间片到期，CPU 一定会切换到另一个进程运行。”**
    - **×**。若时间片到期时就绪队列中**没有其他可运行的同级或更高优先级进程**（仅剩当前进程自己），该进程将继续占用下一个时间片，无需切换。
15. **“四核八线程（开启超线程）的处理器等价于拥有八个独立的物理 CPU 核心。”**
    - **×**。它是 4 个物理核向 OS 呈现 8 个**逻辑 CPU**，利用访存停顿（Memory stall）切换硬件线程；同核两个逻辑线程仍共享执行单元与缓存，不等同于 8 个独立物理核。
16. **“在 Linux 系统中，普通进程的 `nice` 值越大优先级权重越高；单核周期任务的 CPU 利用率超过 $n(2^{1/n}-1)$ 时一定无法用 RM（速率单调）算法调度。”**
    - **×**。两处均错：① Linux `nice` 范围 $-20 \sim 19$，**数值越小权重越高**；② $U \le n(2^{1/n}-1)$ 是 RM 可调度的**充分非必要条件**，超过该界限但 $\le 1$ 时仍可能可调度。

#### 【Lesson 6–7：同步原语、管程与经典同步问题】
17. **“两个线程各自执行一次‘原子读取 `count`，再原子写回旧值加 1’，最终 `count` 一定精确增加 2。”**
    - **×**。单次读和单次写虽各自原子，但**读—改—写整体不原子**；两线程可能同时读到旧值 5，各自写回 6（丢失更新），需用原子读改写指令（如 CAS / `atomic_fetch_add`）或互斥锁。
18. **“两进程严格轮换法（用 `turn` 交替进入）能保证互斥，因此是临界区问题的合格解决方案。”**
    - **×**。严格轮换虽然满足互斥，但当轮到的进程留在剩余区不想进临界区时，另一想进入的进程也会被挡在外面，**违反了‘前进（Progress）’准则**。
19. **“Peterson 算法在理想顺序一致模型下满足互斥、前进和有限等待，但在现代多核处理器上若不加内存屏障可能因指令重排而破坏互斥。”**
    - **√**。（若 `flag[i] = true` 与后续写入/读取发生乱序可见，两个进程可能同时观察到对方 `flag` 为 `false` 而双双进入临界区。）
20. **“直接用 `while (test_and_set(&lock)) ;` 或朴素 CAS 自旋实现的互斥锁，能同时满足临界区的互斥、前进和有限等待三项要求。”**
    - **×**。满足互斥和前进，但**违反有限等待（Bounded waiting）**——锁释放时新到来的线程可能反复抢先，导致某个等待线程饥饿。
21. **“单核处理器上保护较长临界区时，使用忙等自旋锁（Spinlock）比睡眠阻塞互斥锁更高效。”**
    - **×**。单核上自旋线程占着唯一 CPU 空转期间，持有锁的线程根本没有机会上 CPU 执行解锁；自旋锁仅适用于**多核系统且持锁时间极短**（或不可睡眠的中断处理程序）。
22. **“在 POSIX 条件变量中，为什么必须用 `while` 而不是 `if` 检查条件？因为通知线程调用 `pthread_cond_signal` 后等待线程立即直接运行且状态不可能改变。”**
    - **×**。POSIX 采用 **Signal-and-Continue** 语义：通知者仍持锁，等待者在重新竞争获得 `mutex` 前，共享状态可能已被其他线程抢先改写，且可能存在**虚假唤醒**，故必须用 `while` 重查。
23. **“哲学家就餐问题的管程方案（仅当左右两根筷子都可用时才置 `EATING`）彻底消除了死锁，因此保证了每位哲学家都能有限等待。”**
    - **×**。消除死锁不等于消除**饥饿**；若某哲学家的左右两位邻居交替进餐，每次一方放下筷子时另一方仍在进餐，中间这位哲学家仍可能长期饥饿。
24. **“在第一类读者-写者问题（读者优先）中，每个进入的读者都必须执行一次 `wait(rw_mutex)` 以防止写者写入。”**
    - **×**。只有**第一个进入的读者**（`read_count == 1`）执行 `wait(rw_mutex)`，**最后一个退出的读者**（`read_count == 0`）执行 `signal(rw_mutex)`；若每个读者都申请 `rw_mutex` 会导致读者之间相互阻塞，无法并发读取。

### （二）Lesson 2–7 九组高频易混概念秒杀对照表

#### 第 1 组：进程虚拟地址空间五段映射（L3 P.5–6，必考！）
```text
低地址 0  ┌─────────────────────────┐
          │ text（代码段）           │ ← 编译后的可执行机器指令（只读）
          ├─────────────────────────┤
          │ data（已初始化数据段）   │ ← 已初始化的全局变量、static 静态变量（如全局 int y = 15;）
          ├─────────────────────────┤
          │ bss（未初始化数据段）    │ ← 未显式初始化的全局变量、static 变量（如全局 int x; 装载清零）
          ├─────────────────────────┤
          │ heap（堆，向上增长 ↑）   │ ← malloc / new 动态分配的内存块本体
          │           ...           │   （中间空闲区及 mmap 共享库/共享内存映射）
          │ stack（栈，向下增长 ↓）  │ ← 函数调用帧：局部变量、形参、返回地址（注：局部指针变量 int *p 本身在栈，p 指向的对象在堆！）
高地址 max└─────────────────────────┘ ← 顶部含命令行参数 argc/argv 与环境变量
```

#### 第 2 组：同一进程内多线程“共享资源 vs 私有资源”（L4 P.4–5，多选最爱考！）
- **全进程线程共享**：**代码段（`text`）**、**全局/静态数据段（`data`/`bss`）**、**堆（`heap`）**、**虚拟地址空间**、**已打开文件描述符表（open files）**、**信号处置表（signal handlers）**、进程当前工作目录与用户权限、进程组/TGID。
- **每个线程各自私有**：**程序计数器（`PC`）**、**CPU 寄存器集合（含栈指针 SP）**、**栈（`stack`，含用户栈与内核栈）**、**线程局部存储（`TLS`）**、**线程号（`TID`）与调度状态/优先级**、**信号屏蔽字（`signal mask`）**。

#### 第 3 组：四种线程映射模型与底层结构对比（L4 P.19–22, P.57–60）

| 模型 / 平台 | 映射特征 | 一个线程阻塞系统调用时 | 多核并行能力 | 典型实例与课件细节 |
| :--- | :--- | :--- | :--- | :--- |
| **多对一 (Many-to-One)** | 多个用户线程 $\to$ 1 个内核线程 | **整个进程全部阻塞** | **不能多核并行** | GNU Pth（纯用户态库切换极快） |
| **一对一 (One-to-One)** | 1 个用户线程 $\to$ 1 个内核线程 | 其他线程仍可正常运行 | **支持真正并行** | **Linux NPTL**、**常规 Windows 线程**（创建过多耗内核资源） |
| **多对多 (Many-to-Many)** | $M$ 个用户线程复用 $N$ 个内核线程 | 运行时可将其他协程/虚拟线程切到可用内核线程 | **支持并行且轻量** | **Go goroutine**、**Java 21 虚拟线程** |
| **双层模型 (Two-Level)** | 多对多基础上允许单独绑定某个内核线程/LWP | 视是否绑定及 LWP 池而定 | 支持并行 | Solaris 8（注：LWP 是连接用户与内核线程的执行实体） |

- *底层补充*：Windows 线程结构含内核态 **`ETHREAD`、`KTHREAD`（含内核栈）** 与用户态 **`TEB`（含用户栈、TLS）**；Linux 不区分进程与线程结构体，统一用 **`task_struct`**，通过 `clone()` 传递 `CLONE_VM | CLONE_FILES | CLONE_FS | CLONE_SIGHAND | CLONE_THREAD` 共享资源。

#### 第 4 组：五种内核结构与 API / ABI 辨析（L2 P.39–51）
- **API vs ABI**：**API** 是**源代码级**编程接口（管重新编译能否通过）；**ABI** 是**二进制级**接口（管寄存器传参、栈布局、系统调用约定、ELF/PE/Mach-O 格式，决定编译好的二进制能否直接运行）。
- **单体内核（Linux/传统 UNIX）**：核心子系统同处**内核地址空间**直接函数调用，效率高但故障隔离弱；Linux 可加载模块仍在内核态运行，属于**模块化单体内核**。
- **微内核（Mach/QNX/seL4）**：仅 **IPC + 基本内存 + CPU 调度**留在内核，文件系统/驱动作为**用户态进程**靠 **消息传递** 通信，隔离强但跨态切换与 IPC 开销大。
- **混合内核**：**macOS/iOS XNU**（同一内核空间融合 Mach + BSD + I/O Kit）；**Android**（Linux 内核 + **Bionic** C 库 + HAL + **ART** 运行时，非 glibc 桌面环境）。

#### 第 5 组：IPC 进程间通信对比（L3 P.35–66）
- **共享内存 vs 消息传递**：共享内存（`shm_open` + `ftruncate` + `mmap(MAP_SHARED)`）建立映射后读写最快、无需每次进内核，但**必须自行加同步互斥**，且**内部不能存进程本地虚拟地址指针（应存相对偏移量）**；消息传递由内核收发（适合小数据或跨网络），注意有缓冲时 `send/write` 返回仅代表写入本机内核缓冲。
- **匿名管道 `pipe(fd)` vs 命名管道 `FIFO` vs TCP Socket**：
  - `pipe(fd)`：**`fd[0]` 读端、`fd[1]` 写端**，单向字节流，用于父子亲缘进程。
  - `FIFO`：有文件系统路径名，可用于无亲缘本机进程，**数据在内核内存流转不落盘**。
  - `TCP Socket`：有序字节流（**无内置消息边界**，需应用层自定义长度或分隔符）；服务端 `accept()` 返回**新的已连接 socket**，原监听 socket 继续监听。

#### 第 6 组：八大 CPU 调度算法核心特征速查（L5 P.15–44）

| 算法 | 是否抢占 | 核心选择依据 | 突出优点 | 核心缺陷 / 专属考点 |
| :--- | :---: | :--- | :--- | :--- |
| **FCFS** | 非抢占 | 先进入就绪队列者先运行 | 实现最简单、零额外抢占切换开销 | 平均等待长，出现**护航效应（Convoy effect）** |
| **SJF** | 非抢占 | **下一段 CPU burst** 最短者 | 同时到达时**平均等待时间理论最优** | 难以精确预知下一段 CPU 长度；长任务可能**饥饿** |
| **SRTF** | **抢占** | **剩余 CPU burst** 最短者 | 分批到达时平均等待/周转时间更短 | 需预测长度、切换开销多、长任务可能**饥饿** |
| **优先级** | 均可 | 优先级最高者（看清大小方向！） | 区分任务轻重缓急 | 低优先级任务可能**饥饿** $\rightarrow$ 用**老化（Aging）**解决 |
| **RR** | **抢占** | FIFO + 固定时间片 $q$ 轮转 | **响应时间有上界** $(n-1)q$，无饥饿 | 平均等待常长于 SJF；$q$ 太大退化为 FCFS，$q$ 太小切换开销剧增 |
| **MLQ** | 队间可抢占 | 按任务性质固定入不同队列 | 区分前台交互（RR）与后台批处理（FCFS） | **进程固定在原队列不移动**，不够灵活 |
| **MLFQ** | **抢占** | 按运行消耗时间片动态升降队列 | **无需预知长度**即可优待短/交互任务 | 参数设计最复杂（需配老化升级防低队列饥饿） |
| **HRRN** *(往年卷)* | 非抢占 | 响应比 $R_p = \frac{W + B}{B}$ 最高者 | 兼顾短作业与长作业等待时间，防饥饿 | 每次调度需计算所有就绪进程响应比 |

#### 第 7 组：临界区准则与同步工具达标对照（L6 P.8–57）
- **临界区三准则**：① **互斥**（最多 1 人在临界区）；② **前进**（空闲有人申时，剩余区进程不得阻拦且不能无限推迟选择）；③ **有限等待**（发出申请后被他人抢先的次数有上界）。
  - *严格轮换*：满足互斥，**违反前进**。
  - *Peterson 算法*：双进程顺序一致模型下**三项全满足**（等待上界 1 次）；现代乱序多核需加**内存屏障 / Acquire-Release**。
  - *简单 TAS / 简单 CAS 自旋锁*：满足互斥与前进，**违反有限等待**；带 `waiting[n]` 环形交接的改进版 CAS 锁**三项全满足**（等待上界 $n-1$ 次）。
- **互斥量（Mutex） vs 信号量（Semaphore） vs 条件变量（Condition Variable）**：
  - **互斥量**：有明确**持有者**概念，必须**同一线程加锁、同一线程解锁**，保护临界区多字段一致性。
  - **信号量**：维护整型计数值，可由**一个线程 `P/wait`，另一个线程 `V/signal`**；既能控多实例并发名额（初值 $N$），又能做前驱同步（初值 $0$）。
  - **条件变量**：**本身不保存计数状态**（无人等时 `signal` 为空操作），必须配合共享状态变量与互斥锁使用。

### （三）选择题必背 4 大“小计算”秒杀公式

1. **Amdahl 定律（L4 P.13–15，2020 真题）**
   - 设固定任务中**串行部分占比为 $S$**（$0 \le S \le 1$），并行占比为 $1 - S$，$N$ 个 CPU 核的**理想加速比**：
     $$\text{Speedup}(N) = \frac{1}{S + \frac{1 - S}{N}}, \qquad \lim_{N \to \infty} \text{Speedup}(N) = \frac{1}{S}$$
   - *课件原题速算*：
     - $S = 25\%,\ N = 2 \implies \frac{1}{0.25 + 0.75/2} = \frac{1}{0.625} = \mathbf{1.6}$；$N \to \infty$ 上限为 $\mathbf{4}$。
     - $S = 20\%,\ N = 4 \implies \frac{1}{0.20 + 0.80/4} = \frac{1}{0.40} = \mathbf{2.5}$；$N \to \infty$ 上限为 $\mathbf{5}$。

2. **下一段 CPU Burst 指数平均预测（L5 P.24–26）**
   $$\tau_{n+1} = \alpha t_n + (1 - \alpha)\tau_n \quad (0 \le \alpha \le 1)$$
   - 其中 $t_n$ 为刚结束的**实际** CPU 长度，$\tau_n$ 为上次**预测**长度。
   - *课件例题*：$\alpha = 0.5,\ \tau_0 = 10,\ t_0 = 6 \implies \tau_1 = 0.5 \times 6 + 0.5 \times 10 = \mathbf{8}$。

3. **单核实时周期任务可调度性判据（L5 P.54–56，独立可抢占且截止期 $D_i = T_i$）**
   - 总 CPU 利用率：$U = \sum_{i=1}^{n} \frac{C_i}{T_i}$（$C_i$ 为执行时间，$T_i$ 为周期）。
   - **EDF（最早截止时间优先，动态优先级）充要条件**：$U \le 1$。
   - **RM（速率单调，周期越短静态优先级越高）充分条件**：$U \le n\left(2^{1/n} - 1\right)$（记住特殊值：$n=2$ 时约 **$0.828$**，$n=3$ 时约 **$0.780$**，$n \to \infty$ 趋近 $\ln 2 \approx \mathbf{0.693}$）。
   - *课件例题*：$A(C=1, T=4)$，$B(C=2, T=5) \implies U = \frac{1}{4} + \frac{2}{5} = \mathbf{0.65} \le 0.828 \le 1$，RM 与 EDF 均可调度。

4. **Little 定律（L5 P.70）与记录型信号量计数（L6 P.40–42，2018/2019/2020 真题）**
   - **Little 定律**：稳态队列平均等待人数 $L_q = \lambda W_q$（课件：每秒到达 $\lambda = 7$ 个，平均排队 $L_q = 14$ 个 $\implies$ 平均等待时间 $W_q = 14 / 7 = \mathbf{2\text{ 秒}}$）。
   - **记录型信号量 $S$（初值 $S_0$）**：
     - $S > 0$：表示当前**尚余 $S$ 个可用资源许可**，等待进程数为 $0$；
     - $S = 0$：表示资源**恰好分完**，且等待进程数为 $0$；
     - $S < 0$：表示资源已用尽，且当前正有 **$|S|$ 个进程阻塞在该信号量的等待队列中**！
