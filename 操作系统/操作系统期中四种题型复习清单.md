## 一、判断题：复习那些“只对了一半”的说法

四套往年卷都有判断题，并要求错题说明理由。2019、2020、2023 都出现过“生产者与消费者只需互斥”和“多处理器可以靠关中断互斥”。答这类题，最省字的是直接指出**哪种情况会失败**。

| 看到这类说法 | 你应能写出的判定依据 |
|---|---|
| “I/O 完成就直接运行”“系统调用必然换进程” | I/O 完成使等待者变为就绪，还要等调度。同一线程进入内核处理系统调用后，可以返回原线程。 |
| “线程各有一份堆和文件表”“fork 后普通全局变量仍共享” | 同进程线程共享堆、全局数据和文件表，各有栈、PC、寄存器。fork 后普通变量各自修改，继承的文件描述符则可能共享文件偏移。 |
| “时间片越小越高效”“只要先获得 CPU，总等待就短” | 时间片变小可能增加切换开销。一个任务可以立刻获得首次响应，随后却多次排队。 |
| “只加 mutex 就解决生产消费”“关中断能让多核互斥” | 空缓冲区里没有产品，即使消费者拿到锁也无法取。CPU0 屏蔽本地中断时，CPU1 仍能修改共享数据。 |
| “signal 后对方立刻得到锁”“消除死锁就保证人人都能上” | POSIX 的通知者可以继续持锁，等待者要重新得锁。其他线程持续前进时，同一线程仍可能饥饿。 |

**自测。** “两个线程分别原子地读 count，再分别原子地写回旧值加一，最后一定加了 2。” **错。** 初值 5 时，两者都读到 5，再各写回 6。要保护整个读—改—写，可用原子加一或用同一把锁包住整个更新。

## 二、选择题：把容易混的概念成组复习

2018、2019、2020 的卷子都有不定项选择。2020 考过“哪部分内存放可执行代码”“微内核采用哪种 IPC”“哪种算法会发生护航效应”。练习时对每个选项独立判断，考试时按当场题干决定选几个。

| 复习哪组 | 必须分清的特征 |
|---|---|
| L2 系统调用、库函数、Shell、微内核 | Shell 解释命令；printf 可先写用户缓冲；系统调用经受控入口进入内核；微内核常用消息传递连接用户态服务。 |
| L3–4 地址空间、线程资源及映射 | text 放指令，堆放动态分配对象，栈保存调用帧。栈、PC、寄存器、TLS 每线程各有一份。多对一模型中，一个内核线程阻塞可能拖住整组用户线程。 |
| L5 调度算法 | FCFS 对应护航效应；SJF 看下一段 CPU 长度；SRTF 比**剩余**时间；RR 看时间片；MLFQ 允许任务随运行行为换队。某任务由等待变就绪时，可能触发对当前运行者的抢占。 |
| L6–7 同步工具 | 一次更新不可分割看原子读改写；多个字段一致看互斥锁；资源有几个名额看计数信号量；需等共享状态满足看条件变量。按课件记录型信号量的定义，S=−2 表示有两人等这个 S。 |
| 小计算 | Amdahl 理想加速比为 `1/[s+(1−s)/N]`。串行占比 s=20%、4 核时为 2.5 倍。调度题要区分首次响应、总等待和周转。 |

**自测（多选）。** 同一进程内的两个普通线程通常共享哪些内容？A．堆　B．栈指针　C．打开文件表　D．程序计数器。**选 A、C。** 两个线程可以读写同一堆对象、使用同一打开文件表，但各自要能恢复上次运行的位置和调用栈，所以各自保存 PC 和栈指针。

## 三、简答题：准备好能直接写在卷面上的答案

2019、2023 都问过“进程与管程”“死锁与饥饿”“多级反馈队列与 FCFS”；2020 则让考生列出线程三态之间的转换及条件。比较题可写成“各自是什么 → 差在哪 → 用一个场景说明联系”。问执行过程时，按事件顺序写，答到“谁等待、谁唤醒、最后处于什么状态”。

| 优先准备的问法 | 闭卷应能写出的要点 |
|---|---|
| 进程与线程？进程与管程？ | 进程提供资源和地址空间，线程是执行流。管程封装共享数据、访问过程和同步规则；生产进程、消费进程都可调用同一缓冲区管程。 |
| 同步与互斥有什么区别？为什么多核关中断不够？ | 同步约束先后，如先放后取；互斥限制同一时刻的访问者，如一次只能一人改队列下标。关中断只影响当前 CPU，要跨核保护共享数据需原子操作或锁。 |
| 死锁与饥饿有什么区别？ | 死锁时一组执行者互相等待，组内都不能推进；饥饿时某人长期等不到资源，别人仍在推进。读者持续加入，导致写者一直等，是饥饿。 |
| MLFQ 和 FCFS 各怎样调度？ | FCFS 按就绪顺序运行。MLFQ 可按反馈升降队列。课件例子中 Q0 给 8 ms、Q1 给 16 ms、Q2 用 FCFS；无竞争的 30 ms 任务分成 8、16、6 ms 三段。 |
| 写出就绪、运行、等待三态的全部转换。 | 就绪→运行：获得 CPU。运行→就绪：被抢占。运行→等待：阻塞 I/O 或等待事件。等待→就绪：事件发生。 |

**用你刚问的 wait 练一道。** “服务员为什么要在 while 循环中调用 wait(not_empty, mutex)？”

**卷面示范。** 服务员持锁检查传菜位，发现为空就调用 wait，原子地释放 mutex 并进入等待，厨师这时才有机会拿锁放菜。收到通知后，服务员要重新取得 mutex 才从 wait 返回。重新得锁前菜可能已被别人取走，也可能发生虚假唤醒，所以还须用 while 重查 full。

回看课件：[L3 状态与队列，第 7–19 页](<lesson3-processes.pdf#page=7>) · [L5 反馈队列，第 42–44 页](<lesson5-scheduling.pdf#page=42>) · [L7 条件变量，第 34–35 页](<lesson7-sync-example.pdf#page=34>)。

## 四、应用题：优先做两道，再练两种变式

### 第一优先：CPU 调度计算

2018 考平均周转，2019、2023 用同一组进程考四张甘特图和平均等待。先圈出**到达时刻、优先级方向、是否抢占、时间片**，再画图。对每个进程记录首次运行 S、完成 C、到达 A、CPU 总时长 B：

- 周转 = C−A；首次响应 = S−A。
- 等待是所有就绪排队时间之和；题中只有运行和排队时，等待 = C−A−B。有 I/O 时还要扣去阻塞时间。

**闭卷练一次。** P1–P4 均在时刻 0 就绪，按编号入队，CPU 时间为 (9,2,3,2) ms，优先级为 (3,1,2,4)，小数值优先，RR 取 q=1 ms。画完再核对：FCFS、非抢占 SJF、非抢占优先级、RR 的平均等待依次为 **8.5、3.25、5.25、6 ms**。RR 中 P1 从 0 开始、16 完成，等待 16−9=7，不能漏算中途排队。换成不同到达时刻，再练 SRTF。

### 第一优先：有界缓冲区的 P/V 和条件变量

2019、2023 要求写多个生产者、消费者共用单槽的程序；2018 换成最多容纳 20 人的售票厅。今年 L7 第 54–55 页的传菜位可直接改成填空。

```text
单槽初始为空：empty=1，full=0，mutex=1（三个都是信号量）
生产者：P(empty) → P(mutex) → 放入 → V(mutex) → V(full)
消费者：P(full)  → P(mutex) → 取出 → V(mutex) → V(empty)
```

**需要会解释的两处。** 消费者先等产品再拿锁，否则可能在空架前持锁等产品，生产者无法上架。消费者最后归还的是空位，所以执行 V(empty)。如果换成条件变量版本，full 变为受锁保护的布尔值；厨师满时等 not_full，放菜后通知 not_empty；服务员空时等 not_empty，取菜后通知 not_full。

### 接着练：2020 卷的两种程序推演

| 题干 | 先在草稿上追踪 | 可用的核对结果 |
|---|---|---|
| fork 后父子各写一个字节，或主线程与工作线程分别写。文件初始为空，无追加模式。 | 是 fork 前 open 一次还是 fork 后各自 open？偏移是否共享？main 返回之前有无 join？ | 各自 open 后分别写 a、b，最后是 a 或 b；先 open 再 fork 则是 ab 或 ba。主线程写 b 后未 join 就返回，工作线程写 a，还可能只留下 b。 |
| a 按 y、z 加锁，b 按 z、x，c 按 x、y，每人拿齐才释放。 | 分两轮写“已拿哪把、再等哪把”，画从等待者指向持有者的箭头。 | 各拿第一把后，a 等 b 的 z，b 等 c 的 x，c 等 a 的 y，形成环。统一按全局编号递增加锁可破坏循环等待，单改释放顺序无效。 |

**复习取舍。** 上述题型熟练后，再过读者写者和哲学家就餐，尝试用一条执行顺序解释写者饥饿、五人各持一根筷子的死锁。银行家安全序列出现在 2018、2023 旧卷；本次六讲里直接对应的重点是同步中的死锁、锁序与哲学家，限时复习优先做课件里的这几类。
