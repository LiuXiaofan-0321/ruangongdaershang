对称加密：接口、分组与设计语言

理解共享密钥、Gen/Enc/Dec、正确性与双射，分清算法内部的轮和处理长消息的模式。

1. 先区分消息、密钥和算法

第二、三讲已经讲过“可逆加密”和“不可逆的摘要”。现在把可逆加密做成能处理大量数据的工具。发送者和接收者事先持有同一份秘密 K，发送者把明文 M 交给加密算法得到密文 C，接收者用同一 K 解密。共享的是密钥；加解密的操作方向仍可能不同。算法可以公开，密钥需要保密。

例如你与朋友事先约定一把密钥，之后在公开网络上发送密文。窃听者可以知道算法、拿到密文，甚至知道一些明密文对；安全要求仍是其在规定资源内难以恢复其他明文。密钥怎样安全交到朋友手里，是另一个需要解决的问题。对称算法通常速度快、适合批量数据，密钥分发与管理却是关键难点。结构简单不是所有对称算法的必然性质。

2. 三个算法与一个必须成立的等式

沿用第四讲定义2.3，明文空间 ℳ 是允许输入的消息集合，密钥空间 𝒦 是合法密钥集合，密文空间 𝒞 是算法输出集合。方案 SE=(Gen,Enc,Dec)：Gen(param*) 产生 K；Enc(M,K) 产生 C；Dec(C,K) 恢复 M。param* 表示一个或多个参数，例如安全参数；实际生成密钥还需要合格的随机性。

\[\operatorname{Dec}(\operatorname{Enc}(M,K),K)=M\quad(M\in\mathcal M,\ K\text{ 为合法生成的密钥}).\]

这是正确性：合法接收者能恢复原文。它没有证明保密性。例如 Enc(M,K)=M 也满足该等式，却直接公开明文。带随机数或 IV 的实际方案可写 Enc(K,M;IV)，并把解密所需的公开 IV 随密文携带；它不应被误认为额外秘密密钥。

3. 分组密码、流密码与工作模式

bit 是一个0或1，8 bit=1 byte。分组密码每次接收固定 n 位数据，在密钥 K 控制下输出同样 n 位数据。n 是分组长度，k 是密钥长度，二者没有必须相等的规定。AES 的 n=128，k 可为128、192或256；DES 的 n=64，有效 k=56。流密码先由短种子密钥和 IV 生成密钥流，再与消息逐位异或；实现也可以一次生成一个字，而非每次只计算一位。

一份1 MB文件远大于一个分组。工作模式规定如何反复调用分组密码、怎样安排分组之间的依赖。AES-CBC 中，AES 决定“一个128位块怎么加密”，CBC 决定“多个块怎样链接”。只说“使用AES”，还没有交代一套完整的文件加密方案。

4. 为什么固定密钥下必须是双射

{0,1}n 表示所有 n 位串，共有 2n 个。固定 K 后，EK 是这个有限集合上的排列。如果两个不同明文 M、M′ 被加密成相同 C，解密者只见 C 就无法判断是哪一个，因此 EK 必须单射；输入输出集合大小相等，所以同时满射，也就是双射。

\[E_K:\{0,1\}^n\to\{0,1\}^n,\quad D_K=E_K^{-1},\quad D_K(E_K(M))=M.\]

所有 n 位串上的排列共有 (2n)! 种；k 位密钥最多选择其中 2k 种。轮密钥编排是确定性展开，不会凭空增加独立的秘密信息。

混淆、扩散、Feistel 与完整 SPN 演算

看清可逆性从哪里来，完整走完16位SPN的加密和解密，并用实验台检查每一轮。

1. 只有异或，为什么还不够

逐位异或 ⊕ 的规则是相同为0、不同为1。例如课件的 01101001⊕11000101=10101100；再异或同一密钥就恢复，因为 a⊕a=0、a⊕0=a。它很适合把密钥混入状态，但若整个算法只有线性变换与异或，攻击者可利用简单代数关系。设计需要非线性部件。

混淆使密钥与密文之间的关系难以分析，常由密钥混合和非线性 S 盒实现。S 盒就是输入小块后按表查出另一个值。扩散使某个输入位置的影响传播到多个输出位置，常由位置重排、线性混合和多轮迭代实现。香农1949年的思想奠定基础，DES、AES、SM4分别展示不同组合。

雪崩效应通常描述输入翻转1位后，输出约一半位发生变化的统计趋势。它不是“每个输入、每把密钥都恰好翻一半”，也不能独自证明安全。纯位置置换只移动比特，不会把一个1复制成多个1；必须和其他部件、多轮迭代配合。

2. Feistel：整体可逆，但 F 可以不可逆

把分组分成左右两半。第 i 轮先把旧右半搬到左边，再用 F 处理旧右半和轮密钥，与旧左半异或：

\[L_i=R_{i-1},\qquad R_i=L_{i-1}\oplus F(R_{i-1},K_i).\] \[R_{i-1}=L_i,\qquad L_{i-1}=R_i\oplus F(L_i,K_i).\]

逆推第一式直接给出旧右半。将它代入第二式，再异或一次相同 F 值即可得到旧左半。整个过程没有求 F 的逆。因此 DES 的6进4出 S 盒虽然不可逆，DES 整体仍然可逆。多轮时，配合约定的首尾交换，解密可以复用同一轮结构，只把轮密钥逆序。

3. SPN：逐层逆转，两个部件都要可逆

代换—置换网络 SPN 通常对整个状态做密钥加、并行 S 盒代换与可逆线性变换 L。其一般示意式和逆式如下。逆序拆掉最外层 L，再拆 S，最后撤销异或密钥。

\[X_i=L(S(X_{i-1}\oplus K_i)),\quad X_{i-1}=S^{-1}(L^{-1}(X_i))\oplus K_i.\]

这里独立作用在整个状态的 S 和 L 都必须可逆。AES 是 SPN 的典型实例，但具体轮顺序、初始与末轮安排要以 AES 定义为准。不能把一般示意式逐字当作AES每轮流程。PRESENT 则展示4位 S 盒与比特置换的轻量设计。

4. 原课件16位 SPN：不跳过中间轮

每个 S 盒处理4位，4个并行，共16位；4轮，32位主密钥为3A94D63F。十六进制1位表示4个比特。轮密钥是长度16位的滑动窗口：K₁=3A94、K₂=A94D、K₃=94D6、K₄=4D63、K₅=D63F。这里的密钥编排用于教学，不能据此推断安全。

DES：位表、轮函数与可逆结构

按位跟踪DES，完整保留课件中的IP、E、S₁/S₂、P表与课堂查表题。

1. DES 的三种长度

DES由IBM设计，1977年发布为FIPS 46。每块64位，16轮Feistel。密钥常用64位表示，但第8、16、24、32、40、48、56、64位是奇校验位，只有56位参与加密。每个8位字节的1总数需为奇数，例如1010101有4个1，末尾补1得到10101011，共5个1。

奇校验只用于发现部分错误，两个比特同时翻转可能躲过检查；它不提供消息认证，也不增加有效密钥空间。DES的轮密钥是48位，数据左右半块各32位。这四个数字要分别记：64位分组、56位有效主密钥、48位轮密钥、32位半块。

2. 总流程：IP、16轮、交换、IP逆置换

IP只重排64位，不改变比特取值。输出前32位是L₀，后32位是R₀。依次执行Lᵢ=Rᵢ₋₁、Rᵢ=Lᵢ₋₁⊕F(Rᵢ₋₁,Kᵢ)，i=1到16。最后把两半交换，拼成R₁₆‖L₁₆，再做IP−1。下表均按行读，表项是“该输出位取输入的第几位”，不是字节数值。

2. 穷举强度：密钥组合数与攻击工作量

有效密钥空间256≈7.2×1016。若均匀选钥、遍历不重复，且已有足够明密文判别正确候选，最坏256次，平均约255次。8个校验位不会把它变成264。DES已不适合现代保护需求，64位分组也限制同钥数据量；“密钥更长”与“分组更长”解决的是不同风险。

3. DES-XEX3：前后异或白化

\[C=K_3\oplus E_{K_2}(M\oplus K_1),\quad M=K_1\oplus D_{K_2}(C\oplus K_3).\]

先撤销最后的K₃异或，再做DES解密，最后撤销K₁异或。K₁、K₃是64位白化量，K₂是DES有效56位密钥。它只在中间调用一次完整DES。参数总位数不能直接当成已证明的安全强度，分组仍为64位。

4. 双重 DES 为什么挡不住中间相遇

\[C=E_{K_2}(E_{K_1}(M)),\quad M=D_{K_1}(D_{K_2}(C)),\quad E_{K_1}(M)=D_{K_2}(C).\]

攻击者知道一对(M,C)。先遍历256个K₁，把EK₁(M)存表；再遍历256个K₂，算DK₂(C)，查找相同中间值。每个匹配给出候选密钥对，再用其他明密文对排除误配。时间约257次DES加解密，存储约256项，而不是朴素2112。

一对64位明密文下，约2112/264=248个随机密钥对可能误配；所以“找到一个相遇”不能直接宣布找到唯一密钥。这个例子说明算法组合数2112不自动意味着112位攻击难度。

4. MixColumns 的数学铺垫：字节是多项式

GF(2⁸)不是“普通整数除以256取余”。把一个字节的8位作为x⁷到x⁰的系数，系数在模2下运算，所以加减都是异或。例如63=01100011，表示x⁶+x⁵+x+1。乘法先乘多项式，再模不可约多项式m(x)=x⁸+x⁴+x³+x+1，编码为11B，得到仍小于8次的多项式。

乘02就是乘x：先左移，若原最高位是1，产生的x⁸按x⁸≡x⁴+x³+x+1约减。实现为xtime(a)=((a<<1)&FF)⊕(最高位为1时取1B，否则取00)。乘03=(02×a)⊕a。例如02×63=C6，没有溢出；02×E0=1C0⊕11B=DB，不能只截断为C0。

\[\begin{pmatrix}b_0\\b_1\\b_2\\b_3\end{pmatrix}=\begin{pmatrix}02&03&01&01\\01&02&03&01\\01&01&02&03\\03&01&01&02\end{pmatrix}\begin{pmatrix}a_0\\a_1\\a_2\\a_3\end{pmatrix}\quad\text{（矩阵元素为十六进制，运算在GF}(2^8)\text{）}.\]

ECB 与 CBC：长消息、填充与重复泄露

用四位玩具密码学习完整分组调用、CBC链式依赖与填充规则，理解图像轮廓为何泄露。

1. 为什么需要模式和填充

分组密码只承诺处理一个固定长度块。第五讲在这个核心外面加上组织规则，处理文件、图片和网络消息。记Mᵢ为第i个明文块、Cᵢ为第i个密文块，EK和DK分别是一次完整分组加解密，不是AES的一轮。

ECB、普通CBC要求输入长度为整块数。若末块不足，需要无歧义填充。以按字节的PKCS#7为理解补充：块长b字节，缺p字节就补p个值为p的字节。AES的b=16；若消息14字节，补02 02；若正好16字节，仍需补整块16个10（十六进制），防止把数据末尾误认成填充。末尾补0若无原长约定，会无法区分原文0与填充0。

2. ECB：同样的块得到同样的密文

\[C_i=E_K(M_i),\qquad M_i=D_K(C_i).\]

各块独立，可并行加解密。固定密钥的双射意味着Mᵢ=Mⱼ当且仅当Cᵢ=Cⱼ。即使不知道每块内容，也能认出重复位置。攻击者还可以复制、删除、交换整块，接收者仍逐块解密；没有额外认证，就不知道被改过。

3. CBC：先异或，再加密

\[C_0=IV,\qquad C_i=E_K(M_i\oplus C_{i-1}),\qquad M_i=D_K(C_i)\oplus C_{i-1}.\]

第一块没有前块，使用初始化向量IV，它与分组等长。IV一般公开随密文发送，但应每次按要求新生成且在选定消息时不可预测，并保护其完整性。解密不要求IV保密，要求双方用同一个正确IV。CBC加密要等Cᵢ₋₁，所以串行；密文全已获得时，各DK(Cᵢ)可同时算，再与已知前块异或，因此可并行解密。

CFB、OFB、CTR：反馈对象与 IV 条件

比较三种密钥流模式，区分串行生成、可并行解密和跨消息的唯一性约束。

1. 三种模式都先产生掩码，再异或消息

CFB、OFB、CTR把完整EK当作密钥流生成部件。消息只参与异或，因此解密仍调用EK，不用DK。但“喂给E的输入是什么”决定依赖关系与安全要求。以下CFB按课件采用整块反馈CFB-n；CFB-8、CFB-1等分段变体要另外分析移位寄存器。

2. CFB：加密前一个密文

\[C_0=IV,\qquad C_i=M_i\oplus E_K(C_{i-1}),\qquad M_i=C_i\oplus E_K(C_{i-1}).\]

第一步E(IV)得到第一段掩码，第二步E(C₁)得到第二段。反馈的是密文，所以加密依赖前一块结果，不能提前生成完整密钥流。密文已知时可并行解密。IV应新生成且不可预测，同钥复用IV会重复首段掩码，泄露首段明文异或。

3. OFB：加密前一次输出

\[O_0=IV,\quad O_i=E_K(O_{i-1}),\quad C_i=M_i\oplus O_i,\quad M_i=C_i\oplus O_i.\]

O₂=E(E(IV))，反馈完全不看明文或密文，所以可在消息到达前生成。密钥流内部仍是串行：O₂要等O₁。已有O序列时，异或消息可并行。同一密钥下IV必须唯一，且应避免一个消息的内部O值被另一个消息当IV，防止密钥流重叠。通常采用规范规定的IV生成方法。

4. CTR：加密互不重复的计数器块

\[S_i=E_K(\operatorname{ctr}_i),\quad C_i=M_i\oplus S_i,\quad M_i=C_i\oplus S_i.\]

ctrᵢ与分组等长，常由nonce（每消息唯一量）与块计数器拼成。各块直接算E(ctrᵢ)，可并行、预计算、随机访问。接收第100块时，知道该块计数器就可直接解密。计数器不必秘密；关键是同一K下所有完整计数器输入不得重复，约束横跨不同消息。计数器溢出回绕、两个消息使用重叠计数范围，都会重用密钥流。

3. 原作业的玩具密码不会“约半块损坏”

CTR的C₂=0010变为1010，掩码仍0001，M₂′=1011，与原0011差1000；其他块不变。若换成AES等强分组密码，CBC当前块通常发生广泛变化，下一块仍只有对应最高位翻转；CTR仍仅一位翻转。这里“约一半”是典型统计预期，不是每次必须精确一半。

流密码：一次一密、密钥流重用与 hello 作业

理解计算安全与信息论安全的差别，完成重复密钥流作业，并推导已知明文与定向篡改。

1. 一次一密怎样变成可部署的流密码

一次一密要求密钥流均匀随机、与消息独立、保密、至少与消息等长、绝不复用。满足条件可得到信息论保密，但密钥分发成本很高。课件“目前只有一次性密码本无条件安全”需收窄：OTP是典型实例，并非所有信息论安全构造的唯一形式。

流密码以较短的秘密种子和公开IV初始化确定性生成器，输出很长的密钥流。两端输入相同、运行顺序相同，就得到相同流。现代密钥流需要密码学不可预测性；0/1大致均衡、周期很长、统计检验通过都只是部分要求，不能保证安全。一个简单交替0101…也很均衡，却完全可预测。

\[c_i=m_i\oplus k_i,\qquad c_i\oplus k_i=m_i\oplus(k_i\oplus k_i)=m_i.\]

这里种子密钥小写k与密钥流位kᵢ角色不同。流密码的长输出依然受短种子能提供的计算安全限制；它不会自动继承OTP的信息论保证。ZUC每拍输出32位，再把这些字展开成比特流。

2. 复用流的代数灾难

\[c=m\oplus s,\quad c'=m'\oplus s\quad\Longrightarrow\quad c\oplus c'=m\oplus m'.\] \[m\text{ 已知时：}\quad s=c\oplus m,\qquad m'=c'\oplus s.\]

已知一个位置的明文只能恢复对应位置的密钥流，不能据此直接断言整个安全生成器种子已泄露；但另一条复用同段流的明文已无法保密。同钥不同IV若保证规范要求的唯一性，可避免生成相同流。这里风险是“同一段流复用”，不是“秘密种子只允许加密一条消息”。

3. 课件LCG反例需要条件

线性同余Xₙ₊₁=(aXₙ+c) modm不适合直接做密钥流。若m已知且相邻输出差可逆，几个输出便可恢复a、c。若m未知，可构造差分tᵢ=Xᵢ₊₁−Xᵢ、uᵢ=tᵢ₊₂tᵢ−tᵢ₊₁²，真实m整除各uᵢ，再用多个uᵢ的最大公因数得到m候选。四个输出仅提供一个u，不能普遍唯一恢复m；u=0、差分不可逆或截断输出都会改变分析。完整基础推导见第三讲LCG章节。

1. ZUC 的三层分工

ZUC以祖冲之的名字命名。本课介绍128位KEY与128位IV输入、每拍32位密钥字输出的版本。课件列出2011年LTE、2012年GM/T 0001、2016年GB/T 33133及2020年ISO/IEC 18033-4的标准化沿革。这里研究产生流的核心，下一章再研究如何构造机密性算法的IV。ZUC也可用于完整性算法，但本课不推导128-EIA3。

2. 两种加法、两种位宽

⊕是逐位异或，不进位。⊞是普通整数加法后mod2³²，保留32位。LFSR使用的是mod(2³¹−1)，不能截断31位后就认为完成取模。‖表示拼接，不是加法。ROL₃₁和ROL₃₂的环宽不同；W≫1在初始化中是逻辑右移，丢弃最低位、高端补0，不是循环右移。

3. 密钥装入：8+15+8=31

4. LFSR反馈与两种模式

\[p=2^{31}-1,\quad v=\big(2^{15}s_{15}+2^{17}s_{13}+2^{21}s_{10}+2^{20}s_4+(1+2^8)s_0\big)\bmod p.\] \[s_{16}=\begin{cases}(v+u)\bmod p,&\text{初始化，}u=W\gg1,\\v,&\text{工作模式。}\end{cases}\]

若结果s₁₆=0，则置s₁₆=p，用全1的31位字表示模p的零类，维持寄存器取值在1到p。然后把旧(s₁,…,s₁₅,s₁₆)作为新(s₀,…,s₁₅)。每次移位是一整个31位单元前移，不是把整个数组按1个bit左移。

5. 为什么快速模运算可以“绕回来”

因为2³¹≡1(modp)，乘2ᵏ可按31位循环左移实现。若把a分为将移出高端的部分q和留在低端的部分r，则2ᵏa=q·2³¹+r≡q+r；高端移出部分回到低端正好实现同余。对全1表示p的零类，循环移位仍是全1，应理解为规范表示，而非标准余数0。

\[2^k a\equiv\operatorname{ROL}_{31}(a,k)\pmod p.\] \[a(2^i+2^j+2^k)\equiv\operatorname{ROL}_{31}(a,i)+\operatorname{ROL}_{31}(a,j)+\operatorname{ROL}_{31}(a,k)\pmod p.\]

模加时c=a+b，再c=(c&7FFFFFFF)+(c≫31)，把溢出的2³¹进位作为1加回。两操作数在1…p内时结果也在1…p，是该表示体系下的模加；若另外使用标准余数约定，结果p还需解释为0。多个操作数要逐次做规范模加，不能无界累加后只折叠一次。

课件例7FFFFFF0+20=80000010；低31位为00000010，进位1加回得到11。因此反馈v可由4个31位循环移位、s₀本身、ROL₃₁(s₀,8)做模加组成，无须大整数除法。汉明重量是二进制1的个数；系数2ᵏ仅一个1。

ZUC 完整运行顺序与机密性算法参数题

展开BR、F和初始化时序，逐位构造EEA3的IV，完成1000比特课堂例题。

1. BR：从分散寄存器拼接128位

\[\begin{aligned}X_0&=s_{15H}\parallel s_{14L},&X_1&=s_{11L}\parallel s_{9H},\\X_2&=s_{7L}\parallel s_{5H},&X_3&=s_{2L}\parallel s_{0H}.\end{aligned}\]

每次拼两个16位半字，前项放高半，后项放低半。sᵢH=(sᵢ≫15)&FFFF，sᵢL=sᵢ&FFFF。例如X₀=((s₁₅&7FFF8000)<<1)|(s₁₄&FFFF)，保持32位。X₀到X₂给F；X₃留作最终异或，不能把四个字全部作为F的直接输入。

2. F：先读旧状态，再更新两个记忆单元

\[\begin{aligned}W&=(X_0\oplus R_1)\boxplus R_2,\\W_1&=R_1\boxplus X_1,\quad W_2=R_2\oplus X_2,\\R_1^{new}&=S(L_1(W_{1L}\parallel W_{2H})),\\R_2^{new}&=S(L_2(W_{2L}\parallel W_{1H})).\end{aligned}\]

W、W₁、W₂全部用旧R₁、R₂计算，再一起更新。W₁、W₂是32位，所以H/L按31…16和15…0取，不同于31位s。交叉拼接时把低半放到新字高半，例如W₁L‖W₂H=(W₁&FFFF)<<16 | (W₂≫16)。

\[\begin{aligned}L_1(X)&=X\oplus\operatorname{ROL}_{32}(X,2)\oplus\operatorname{ROL}_{32}(X,10)\oplus\operatorname{ROL}_{32}(X,18)\oplus\operatorname{ROL}_{32}(X,24),\\L_2(X)&=X\oplus\operatorname{ROL}_{32}(X,8)\oplus\operatorname{ROL}_{32}(X,14)\oplus\operatorname{ROL}_{32}(X,22)\oplus\operatorname{ROL}_{32}(X,30).\end{aligned}\]

S对高到低4字节依次用S₀、S₁、S₀、S₁；课件记S₂=S₀、S₃=S₁。这些是ZUC专用S盒，不能换成AES或SM4。课件未给两张具体256项表，本指南保留课件的完整算法表达；若进一步实现ZUC，需使用ETSI/SAGE ZUC v1.6的S₀/S₁参数表，不要用自造表补齐。本指南的IV实验不调用ZUC核心，避免把演示误认成实际加密。

MAC 与 HMAC：来源、完整性与完整计算流程

区分加密、裸哈希与消息认证，掌握HMAC内外层、64字节密钥处理和全部课堂题。

1. MAC 回答“有没有被改”，不隐藏内容

消息认证码MAC，又称消息鉴别码，用共享密钥K把消息M变成标签T。发送M‖T，接收者以同一K重算标签并比较。旁观者仍可读到M，故MAC本身不提供保密。裸Hash人人都能重算，不能替代MAC抵抗恶意修改。

\[T=\operatorname{Co}(K,M),\quad \operatorname{Ver}(K,M,T)=\begin{cases}1,&T=\operatorname{Co}(K,M),\\0,&\text{否则}.\end{cases}\] \[\operatorname{Ver}(K,M,\operatorname{Co}(K,M))=1.\]

这是课件定义2.4：K∈𝒦，M∈ℳ，标签T∈ℳ′；安全要求是攻击者即使获得许多消息及标签，也难以为未获认证的新消息生成合法标签。合法标签说明发送方持有共享K，并不能在多名持钥者之间证明具体是谁。双方都能生成标签，所以MAC不具有数字签名的公开验证与不可否认性质。

flowchart LR
 A["发送方：M和共享K"] --> B["Co生成标签T"]
 B --> C["发送M与T"]
 C --> D["接收方：同K重算T星"]
 D --> E["比较收到T：一致才接受"]

消息与标签均可公开，密钥不发送。验证成功必须建立在密钥安全和MAC安全的前提下。

课件边界 · 删除、重放与身份

MAC能发现被认证消息内部的删改和伪造，不能阻止整条消息被丢弃，也不能自动判断收到的是昨天的合法消息。防重放应把序号、会话标识等纳入认证，并维护接收状态。网络身份还依赖共享密钥怎样绑定到参与者。

2. HMAC：内外两层带密钥的哈希

HMAC的研究构造发表于1996年，RFC 2104发表于1997年。设哈希输入分组长B字节、输出长h字节（h≤B）。先将K规范化为B字节K′，然后内层处理消息，外层再封装内层摘要。ipad是B个36，opad是B个5C，值均为十六进制。

\[K'=\begin{cases}H(K)\parallel0^{8(B-h)},&|K|>B,\\K\parallel0^{8(B-|K|)},&|K|\le B,\end{cases}\quad |K|\text{ 以字节计}.\] \[I=H((K'\oplus\operatorname{ipad})\parallel M),\qquad T=H((K'\oplus\operatorname{opad})\parallel I).\]

先比较的是密钥长度与哈希输入分组长度，不是摘要长度。HMAC-SM3中B=64字节、h=32字节，输出标签默认32字节。K′异或ipad后与M拼接，不是把M也与ipad异或；内层摘要必须以原始32字节接入外层，不能把64字符十六进制打印文本当32字节摘要。

flowchart TD
 K["K规范化成64字节K撇"] --> I["K撇异或ipad，与M拼接"]
 I --> H["SM3：内层32字节摘要"]
 K --> O["K撇异或opad"]
 O --> J["与内层原始摘要拼接"]
 H --> J
 J --> T["SM3：最终32字节HMAC"]

HMAC-SM3的64字节是输入分组长，32字节是输出长。两次完整哈希调用可能各含多次压缩。

3. 课堂题：密钥规范化和两个字节异或

若K′首字节4B=01001011，ipad首字节36=00110110，异或得01111101=7D；opad首字节5C=01011100，异或得00010111=17。这里补0是HMAC密钥规范化，完全不同于SM3消息的“1、若干0、长度”填充，也不同于CBC的PKCS#7填充。

“内外两次哈希调用”不表示只做两次压缩函数。SM3内层前缀已有64字节，后面还要拼M并做消息填充；外层输入64+32=96字节，再由SM3正常填充、分块处理。哈希函数内部细节见第三讲SM3。

HMAC-SM3比较密钥长度时用；等长密钥；MAC不自动提供。

先自己思考 · 为什么消息与H(M)一起发送，不能替代M与HMAC(K,M)？

攻击者改M为M′后能公开计算H(M′)，一起替换即可。HMAC多了秘密K，攻击者没有K就难以为M′生成合法标签。若攻击者把旧合法(M,T)原样重放，T仍正确，所以协议仍需验证被认证序号、会话与时效。

评分采分点：裸哈希可重算2分；共享秘密的作用2分；指出重放仍需状态1分。

CBC-MAC、KDF 与 HKDF：条件、推导和作业

证明变长CBC-MAC的反例，修正熵的误解，完整推导HKDF并完成600位派生作业。

1. CBC-MAC：零初值，只输出最后一块

\[C_0=0^n,\quad C_i=E_K(M_i\oplus C_{i-1}),\quad T=C_t.\]

它长得像CBC加密，但目标是认证，只发送最终标签，不发送完整加密链。基本CBC-MAC要求同一密钥认证的消息来自固定长度域，输入分块与编码也必须无歧义；填充不足一块并不自动修复跨长度伪造。IV固定为全0，不能像CBC加密那样随消息随机选IV。

flowchart LR
 Z["固定零初值"] --> A["异或M1"]
 A --> E1["E_K"]
 E1 --> B["异或M2"]
 B --> E2["E_K"]
 E2 --> C["继续链接至末块"]
 C --> T["只输出最后标签T"]

基本CBC-MAC适用固定长度域。变长消息应采用经设计的改进构造，例如CMAC。

先自己思考 · 证明直接把基本CBC-MAC用于变长消息会被伪造

已知一个单块消息M的标签T=EK(M)。构造两块新消息M‖(M⊕T)。第一块链值为T；第二块进入E的输入是(M⊕T)⊕T=M，末标签再次为T。攻击者没有密钥，却为新的两块消息给出正确标签。这个示例假定验证器直接接受不同整块长度的基本CBC-MAC；正规定长域或合适改进构造会排除这类跨长度攻击。

评分采分点：已知标签关系1分；构造新消息2分；两块递推消去T两分；说明变长条件1分。

2. KDF 的目标：提取、扩展和用途隔离

课件定义2.5写作KDF:𝒦×𝒮×ℕ→𝒯，输入派生材料σ、盐salt、迭代次数r，输出密钥k。σ可以来自已有密钥、协商共享秘密或口令；salt用于区分输入实例、减少预计算复用，r是某些口令KDF的成本参数。不同KDF接口不同，不是每一种都有可省略的salt和r。HKDF还有info和输出长度L，但没有用于口令加固的r。

必须修正 · KDF不能凭空创造秘密熵

P43“由低熵输入生成高熵输出”不能按字面记忆。对固定公开salt，确定性函数不会增加输入的秘密信息熵。若σ只有100万种候选，即使输出256位，攻击者仍可逐一派生这100万种候选。KDF可以整理已有熵、产生用途不同的伪随机密钥，口令KDF可提高每次猜测成本，但输出长不等于秘密更难猜。

从“随机来源”到“格式合适的密钥”是两个步骤：材料应有足够不可预测性，KDF负责转换及域隔离。把同一派生结果同时当加密钥、MAC钥可能混淆用途；应以规范定义的info或标签派生不同子密钥。

3. HKDF：Extract 提取，再 Expand 扩展

下面先按课件使用比特单位：底层HMAC输出l位，要求输出L位，N=⌈L/l⌉。Co的第一个参数始终是HMAC密钥。Extract用salt作HMAC密钥、σ作消息，得到prk；Expand用prk作HMAC密钥。info是公开上下文，例如协议版本、方向、用途标签。

\[\begin{aligned}\operatorname{prk}&=\operatorname{HMAC}(\operatorname{salt},\sigma),\\T(0)&=\varepsilon,\quad N=\lceil L/l\rceil,\\T(i)&=\operatorname{HMAC}(\operatorname{prk},T(i-1)\parallel\operatorname{info}\parallel\operatorname{I2OSP}(i,1)),\quad1\le i\le N,\\\operatorname{OKM}&=\operatorname{left}_L(T(1)\parallel\cdots\parallel T(N)).\end{aligned}\]

ε是空串，不是一个00字节。计数器i编码成单字节01、02、03…FF，而不是字符“1”或四字节整数。RFC 5869的L、HashLen都以字节计，最大L≤255×HashLen；课件以比特计的对应上限是L≤255l。若salt省略，RFC约定用HashLen个00。HKDF-SM3中HashLen=32字节，上限8160字节。HKDF适合已有足够熵的材料，不能直接替代专为低熵口令设计的慢速KDF。

4. 两个长度例题：512位与600位

HMAC-SM3的l=256位。L=512时N=2，拼T₁与T₂正好64字节。第五讲P47作业L=600时，600/256=2.34375，向上取整N=3。

先自己思考 · 写出600位派生的T(1)、T(2)、T(3)，以及截取位置
\[\begin{aligned}T(1)&=\operatorname{HMAC}(\operatorname{prk},\operatorname{info}\parallel01_{16}),\\T(2)&=\operatorname{HMAC}(\operatorname{prk},T(1)\parallel\operatorname{info}\parallel02_{16}),\\T(3)&=\operatorname{HMAC}(\operatorname{prk},T(2)\parallel\operatorname{info}\parallel03_{16}).\end{aligned}\]

前两块共512位，还缺88位=11字节。因此输出T(1)的32字节、T(2)的32字节、T(3)最高的11字节，共75字节。不是把三块全部96字节输出，也不是取T(3)最低88位。标准HKDF要求按字节计长度，本题600恰好是8的倍数，可直接对应75字节；非整字节长度则需另明确截位协议。

评分采分点：N=3一分；三个递推各2分；前两块512位一分；末块88位=11字节两分。

5. 可运行参考代码：HMAC-SM3 与 HKDF-SM3

下面代码使用Python标准库，需底层hashlib提供SM3；若环境缺少SM3会明确报错。它以字节处理，包含RFC长度上限检查，并独立实现内外层HMAC再与标准hmac库核对。代码用于核对推导，不要求零基础学习者先掌握编程。

import hashlib
import hmac

def sm3(data):
    return hashlib.new("sm3", data).digest()

def hmac_sm3(key, message):
    if len(key) > 64:
        key = sm3(key)
    key = key + bytes(64 - len(key))
    inner_key = bytes(x ^ 0x36 for x in key)
    outer_key = bytes(x ^ 0x5C for x in key)
    return sm3(outer_key + sm3(inner_key + message))

def hkdf_sm3(ikm, salt, info, length):
    if not isinstance(length, int) or not 0 <= length <= 255 * 32:
        raise ValueError("length must be 0..8160 bytes")
    if salt is None:
        salt = bytes(32)
    prk = hmac_sm3(salt, ikm)
    previous = b""
    output = bytearray()
    count = (length + 31) // 32
    for i in range(1, count + 1):
        previous = hmac_sm3(prk, previous + info + bytes([i]))
        output.extend(previous)
    return bytes(output[:length])

key = bytes([0x4B]) * 20
message = b"hello"
assert hmac_sm3(key, message) == hmac.new(key, message, "sm3").digest()
derived = hkdf_sm3(bytes(range(32)), b"course-salt", b"encryption", 75)
assert len(derived) == 75
print(derived.hex())
