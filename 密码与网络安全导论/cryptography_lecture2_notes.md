## 二、古典密码学

### 1. 跳舞小人密码：单表代换

福尔摩斯故事中的“跳舞小人”密码，让每个小人对应一个英文字母，本质是单表代换。相同明文字母每次都替换成同一个密文符号。

它可以被频率分析破解：统计密文符号出现次数，再结合常见单词、重复结构逐步恢复替换表。英语中的高频字母经过代换后仍然对应高频密文符号，这就是它的根本弱点。

### 2. Scytale 棍子加密：置换

斯巴达人把羊皮纸缠在固定粗细的木棍上，沿棍身写军令。取下后字母顺序被打乱，只有用同样粗细的木棍重新缠绕才能读出。

这是置换密码：字母本身不变，只改变位置，木棍粗细就是密钥。

记忆口诀：**代换改变内容，置换改变位置。**

### 3. 模运算与乘法逆元

密码学通常把字母映射为数字：`A=0, B=1, ..., Z=25`，再在模 26 的意义下运算。例如 `25+3=28≡2 (mod 26)`，所以 Z 往后移 3 位得到 C。

若 `3×9=27≡1 (mod 26)`，则 9 是 3 在模 26 下的乘法逆元。a 在模 m 下可逆，当且仅当 `gcd(a,m)=1`。逆元是仿射密码和 RSA 等算法的重要数学基础。

### 4. 凯撒密码和移位密码

移位密码的公式是：

```text
E(x) = (x + K) mod 26
D(y) = (y - K) mod 26
```

例如 K=3：

```text
HELLOWORLD -> KHOORZRUOG
```

凯撒密码是移位密码 K=3 的历史特例。它的密钥只有 26 种，攻击者可以全部尝试。

```text
PHHW PH DIWHU WKH SDUWB
-> MEET ME AFTER THE PARTY
```

这说明第一种攻击范式：**密钥空间太小，穷举攻击可行。**

### 5. 单表代换密码

单表代换为 26 个字母建立任意排列，密钥空间是 `26!≈4×10^26`，几乎不可能靠穷举完成。但它仍然保留语言统计规律：高频字母、常见词和重复结构都还存在，因此容易被频率分析破解。

关键结论：**密钥空间大，不等于密码体制安全。**

### 6. 维吉尼亚密码：多表代换

维吉尼亚密码用一个密钥字循环生成密钥流。例如密钥 CIPHER：

```text
明文:   H E L L O W O R L D
密钥流: C I P H E R C I P H
```

每一位的明文数字与密钥数字相加，再对 26 取模。由于相同明文字母在不同位置可以使用不同移位量，部分频率特征会被隐藏。

但密钥循环使用会形成周期。攻击者可以用卡西斯基检验观察重复片段间距，或用重合指数法推测密钥长度。一旦周期暴露，多表代换就会退化为若干个单表代换。

### 7. 置换密码

置换密码只重排位置，例如 `HELLO -> ELHOL`。若置换为 `K=(3,5,1,6,4,2)`，则第 i 个输出取原串第 K_i 个字符；解密使用逆置换。

最容易错的是下标方向，记住：**第 i 个输出，取原串第 K_i 个。**

### 8. 四种古典密码对比

| 密码 | 核心操作 | 主要弱点 |
|---|---|---|
| 移位密码 | 固定移位 | 只有 26 个密钥 |
| 单表代换 | 一张替换表 | 保留频率特征 |
| 维吉尼亚密码 | 多张替换表 | 密钥周期可被检测 |
| 置换密码 | 重新排列位置 | 字符统计特征仍然保留 |

古典密码共同依赖人工规则，缺少严格安全模型，难以支持大规模通信、身份认证和密钥分发。

## 三、现代密码学与安全性

### 1. 现代密码学的变化

现代密码学不只问“别人能不能看懂”，还会明确攻击者拥有什么能力、什么行为算攻击成功、破解需要多少计算资源，以及信息需要安全多久。

它建立在信息论、数论、计算复杂性和形式化安全模型之上。

### 2. 杂凑函数 Hash

Hash 把任意长度输入映射为固定长度摘要。正向计算容易，反向推回原文困难，主要用于检查完整性。典型算法有 SHA-3 和 SM3。

普通 Hash 不能单独证明消息来自谁，因为任何人都能重新计算摘要。来源认证需要 MAC 或数字签名。

### 3. 对称加密与 MAC

对称加密使用同一个密钥进行加密和解密，速度快，适合大量数据，典型算法有 AES、SM4。

MAC 的输入是消息和共享密钥，输出认证标签，可同时提供完整性和消息来源认证。典型算法有 HMAC、CMAC。

```text
Hash = 消息
MAC  = 消息 + 共享密钥
```

### 4. 公钥加密与数字签名

公钥加密：用接收方公钥加密，接收方用自己的私钥解密，主要提供保密性。典型算法有 RSA、SM2。

数字签名：用自己的私钥签名，别人用自己的公钥验证，主要提供完整性、来源认证和不可否认性。

记忆口诀：**加密用对方公钥，签名用自己私钥。**

### 5. 密钥协商

DH 密钥协商允许双方在不安全信道上建立共享密钥，而不直接传输最终密钥。双方公开 `g^a` 和 `g^b`，最终各自计算 `g^(ab)`。旁观者看到公开量，却难以求出共享值，这依赖离散对数问题的困难性。

实际系统通常先协商会话密钥，再用对称加密传输大量数据。

### 6. 三种安全概念

**无条件安全**：即使攻击者有无限计算能力也无法破解。一次性密码本 OTP 是经典例子，但要求密钥真正随机、与消息等长并且只使用一次。

**计算安全**：假设攻击者计算能力有限，在合理时间内无法攻破。现代密码算法大多属于计算安全，安全性会随算力和攻击技术变化。

**可证明安全**：先明确安全目标和攻击模型，再把破解归约到公认困难问题。它是有条件的安全保证，不代表绝对安全。

### 7. 网络转账案例

| 安全目标 | 对应机制 |
|---|---|
| 转账内容不被窃听 | 对称加密 |
| 金额不能被篡改 | MAC 或数字签名 |
| 确认发送者身份 | MAC 或数字签名 |
| 发送者不能事后否认 | 数字签名 |
| 建立会话密钥 | 密钥协商 |
| 确认公钥属于谁 | PKI 和数字证书 |

现实系统通常组合使用：

```text
密钥协商 -> 对称加密 -> MAC 或数字签名 -> PKI 身份信任
```

## 四、全课最重要的结论

1. 代换改变字母内容，置换改变字母位置。
2. 密钥空间大，不代表密码一定安全。
3. 现代密码学依赖密钥、算法、数学假设和安全模型。
4. Hash 主要解决完整性，MAC 解决完整性和共享密钥下的来源认证。
5. 公钥密码解决密钥分发和身份问题，对称密码负责高效传输大量数据。
6. 数字签名用于认证和不可否认，密钥协商用于建立会话密钥。
7. 一切安全诉求最终都会落到密钥的生成、分发、使用、更新和保护上。
