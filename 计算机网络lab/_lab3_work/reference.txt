一、实验目的
本次实验主要目的包括：
1. 掌握使用Wireshark 捕获并分析IPv4 数据包的方法，理解IP 协议的核心工作机制；
2. 熟悉IPv4 数据报的完整结构，掌握IP 头部各字段的含义、取值规则及作用；
3. 理解IP 分片、TTL（生存时间）、首部校验和等关键机制的设计逻辑，掌握IP 头部校验和的计
算方法；
4. 学会使用tracert 命令追踪Internet 网络路径，直观认识IP 数据包的跨网传输过程。
二、实验内容与实验步骤
本次实验围绕IPv4 协议展开，核心内容包括：
1. 使用Wireshark 捕获HTTP 请求相关的IPv4 数据包，结合wget 命令触发流量、tracert 命
令记录网络路径；
2. 解析IPv4 数据包头部字段，绘制数据报结构示意图；
3. 回答IPv4 协议关键问题（如IP 地址、TTL 初始值、分片判断等）；
4. 根据tracert 结果绘制Internet 网络路径；
5. 按1s 补码算法计算IP 头部校验和并验证。
三、实验环境
1. 操作系统：Windows 11 ，64 位；
2. 分析工具：Wireshark 4.6.1, wget 1.11.4。

2. 回答问题
(1)
结合捕获的数据包及结构分析，回答实验指导手册中提出的中的6 个问题：
What are the IP addresses of your computer and the remote server?
答：本机IP 地址为172.31.55.169；远程服务器IP 地址为182.61.200.110。
(2) Does the Total Length field include the IP header plus IP payload, or just the IP payload?
答：总长度字段包含IP 头部+ 负载。总长度（Total Length）的定义为“整个IPv4 数据
包的字节数”，即“IP 头部长度+IP 负载长度”，例如本次实验中总长度52 字节= 头部
20 字节+ 负载32 字节。
(3) How does the value of the Identification field change or stay the same for different packets?
For instance, does it hold the same value for all packets in a TCP connection or does it
differ for each packet? Is it the same in both directions? Can you see any pattern if the
value does change?
答：未分片数据包中，不同数据包的标识字段取值不同，且同一TCP 连接中，本机→服
务器、服务器→本机两个方向的取值无关联；同一方向的未分片数据包，标识字段随数据
包生成逐次递增1（操作系统通过内部计数器维护，每次生成新数据包计数器+1，赋值给
标识字段）；分片数据包中，同一原始数据包的所有分片，标识字段取值相同（便于接收端
重组）。
(4) What is the initial value of the TTL field for packets sent from your computer? Is it the
maximum possible value, or some lower value?
答：本机发送数据包的TTL 初始值及是否为最大值：初始值128；TTL 字段为8bit，最大
值为255，因此该初始值为较低值（非最大值），不同操作系统默认TTL 不同，Windows
默认128，Linux/Mac 默认64。
(5) How can you tell from looking at a packet that it has not been fragmented? Most often IP
packets in normal operation are not fragmented. But the receiver must have a way to be
sure. Hint: you may need to read your text to confirm a guess.
答：结合Flags 字段与片偏移字段，Flags 字段中“DF=1”（禁止分片）表示路由器不可对

Step 5 IP Header Checksum IP 头部校验和
1. 选择计算对象
根据Step1 中抓取的数据包结果，选择Step2 中研究IPv4 数据包作为计算对象。
头部长度(Header Length): 20 bytes (5)，无可选字段。

(1) 求和：将10 个16 位分组用32 位加法求和：
S = 0x4500 + 0x0034 + 0x8E47 + 0x4000 + 0x8006 + 0x0000
+ 0xAC1F + 0x37A9 + 0xB63D + 0xC86E
S = 0x420B8
(2) 处理进位：将求和结果的高16 位(0x0004) 与低16 位(0x20B8) 相加：
S′ = 0x0004 + 0x20B8 = 0x20BC
(3) 按位取反（1s 补码）：对0x20BC 按位取反，即为校验和：
Checksum =∼(0x20BC) = 0xFFFF −0x20BC = 0xDF43
则该数据包正确的IP 头部校验和应为0xDF43。
3. 接收方校验逻辑验证
接收方收到数据包后（假设校验和字段为0xDF43），按以下步骤验证：
(1) 求和（16 位）：将IP 头部所有10 个16 位分组求和。（利用第2 步处理进位后的求和结果
S′ = 0x20BC）：
Stotal = S′ + Checksum
Stotal = 0x20BC + 0xDF43
Stotal = 0xFFFF
(2) 按位取反：对最终求和结果0xFFFF 进行1s 补码取反：
∼(0xFFFF) = 0x0000
最终结果为0x0000，验证通过，接收该数据包。

五、实验结果总结
通过本次实验，深入了解了IPv4 的结构和追踪的网络路径：
1. 通过Wireshark 成功捕获并解析了IPv4 数据包，验证了IPv4 头部各字段的取值规则（如版本
=4、首部长度=20 字节、TTL=128 等），明确了“总长度包含头部+ 负载”“标识字段用于分
片重组”等关键机制；
2. 掌握了IP 头部校验和的1s 补码计算方法，通过手动计算与数据包实际取值的一致性，验证了
校验和对头部完整性的保障作用；
3. 利用tracert 命令追踪到从本机到百度服务器的网络路径，直观认识到IP 数据包需经过“内
网网关→运营商路由器→目标服务器”等多跃点传输，其中“*”号对应禁用ICMP 响应的路
由器。
