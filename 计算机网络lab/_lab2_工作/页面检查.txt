一实验目的
本实验通过ICMP Echo 流量分析Ethernet II 的字节结构与地址范围，并用广播和组播验
证I/G 判断位，区分抓包显示与实际链路字段。
1. 正确选择网络接口，设置捕获过滤器和MAC 地址解析，保存可复查的抓包文件。
2. 通过协议详情与原始字节确认目的地址、源地址和EtherType 的位置及长度。
3. 对照本机IP、默认网关及ARP 缓存，解释远程ping 的目的MAC 为什么指向下一跳。
4. 识别广播地址与普通组播地址，并回答IEEE 802.3 与Ethernet II 的格式区别。
二实验内容与实验步骤
先在实际联网接口上以icmp 为捕获过滤器，运行四次IPv4 ping 并保存单播迹线；再用
ether multicast 捕获约30 秒背景流量，保存广播与组播迹线。分别检查Ethernet、IPv4 和
ICMP 字段，绘制帧结构图与地址范围图，最后完成实验手册的Turn-in 与拓展问题。
捕获过滤器在开始抓包前决定记录哪些帧；显示过滤器在抓包后筛选已经记录的帧。两
者使用不同语法。例如ether multicast 用于捕获，eth.dst.ig == 1 用于显示。

B。标准以太网帧加上4 B FCS 后为78 B，不包含前导码和帧起始定界符SFD。这里的74 B

检查MAC 地址和协议封装，但不能直接把上述标准以太网帧长当成无线链路实际发送的
802.11 帧长。VLAN 标签和FCS 是否可见也取决于网卡、驱动与抓取位置。

以太网广播地址为ff:ff:ff:ff:ff:ff，48 位全部为1。判断单播或组播的I/G 位是目的MAC
第一字节的最低有效位，即bit 0：0 表示Individual，1 表示Group。广播也是组地址的一个
特殊取值；组地址不一定是广播。［2］
例如ff 的最低位为1；普通组播地址常以01 或33 开头，它们的最低位也为1。以太网
在每个地址字节内先发送最低位，所以手册中的“线上先发送的第一位”与这里的最低有效位
一致。旁边的U/L 位即bit 1 判断全局或本地管理，与I/G 的收件对象判断不同。
若样本为ARP 请求，应结合Opcode、Sender IP 和Target IP 解释作用。一般地址解析请
求询问某个IP 对应的MAC；只有满足相应特征时，才能称为Gratuitous ARP 或冲突检测流
量。不能因“目的MAC 是广播”就把所有ARP 帧都写成免费ARP。

4 5 抓包现象与问题分析
抓不到ping 时，首先区分目标不回复与选错接口：命令行成功而迹线为空，应核对实际
路由、捕获接口和过滤器；域名使用IPv6 时，应使用-4 重新生成IPv4 流量。VPN 会改变路

物理网关。
未观察到广播或普通组播，可能与网络中设备较少、无线网络抑制广播、抓包接口选择
或观测时长有关。可先延长自然背景观测并记录时长；如需主动生成流量，应另行保存迹
线，标注生成方式，不能把主动流量计入原先30 秒的背景统计。

5 2 IEEE 802 3 拓展问题
1. 首部长度。Ethernet II 与IEEE 802.3 的MAC 首部都为14 B，区别在末尾两字节被解
释为Type 或Length。IEEE 802.3 后通常还接LLC：当Control 为单字节UI 格式时，DSAP、
SSAP、Control 共3 B，合计17 B；若再接5 B SNAP，则合计22 B。其他LLC 控制格式可
能用两字节Control，因此需逐帧测量。Padding 和FCS 在尾部，不应计入前部首部长度。
［3］
2. 帧类型判别。查看源MAC 后的16 位Length/Type 字段：值不大于1500 时按长度解
释，值不小于1536（0x0600）时按EtherType 解释。1501–1535 不属于这两种常规取值范
围。识别LLC 的迹线还需确认底层链路确为IEEE 802.3，因为无线802.11 帧也可带LLC。
［4］
3. 上层协议识别。LLC 使用服务访问点字段区分协议，接收端主要看DSAP。若为
SNAP，常见DSAP=0xaa、SSAP=0xaa、Control=0x03，随后五字节为OUI 和协议标识；
OUI=0x000000 时，两字节协议标识沿用EtherType，例如IPv4 为0x0800。［3］
拓展实测记录：［在本人迹线中用llc 查找；有样本则记录帧号、Length、LLC 字段和长
度，无样本则据实说明未观察到。］

步骤2 设置捕获接口并拍第1 张
1. 打开Wireshark。如果正在抓包，先点左上角红色方块停止。按Ctrl + K，或点击顶部“捕
获”→“选项”。
2. 在“输入/ Input”标签的接口列表中单击WLAN。若列表有多行被选中，先单击目标接口，
只保留它；确认旁边链路类型为Ethernet。
3. 在窗口下方“Capture filter for selected interfaces / 所选接口的捕获过滤器”输入icmp。它是捕
获选项窗口里的输入框，不是主窗口顶部的绿色显示过滤器。绿色表示语法有效。
4. 取消“在所有接口上启用混杂模式/ Enable promiscuous mode on all interfaces”的勾选；如果
接口行还有单独的混杂模式设置，也保持关闭。无线“监控模式”保持关闭。
5. 此时先别点开始。截取窗口，包含选中接口、Ethernet、icmp 和混杂模式设置，命名为01_
单播捕获设置.png。

步骤5 展开单播帧并拍第4 张
1. 在主窗口顶部显示过滤器中输入icmp，按回车。它可以列出请求和回复。单击第一条Info
中写着Echo (ping) request 的记录。
2. 中间协议详情区左边的小三角表示展开。依次展开Frame、Ethernet II、Internet Protocol
Version 4、Internet Control Message Protocol。
3. 保留以下字段可见：Frame 的长度；Ethernet 的Destination、Source、Type；IPv4 的Header
Length、Total Length、Protocol、Source Address、Destination Address；ICMP 的Type 和
Code。
4. 点击Ethernet II 文字整行，不是小三角。底部十六进制会高亮前14 个字节。截图要同时带

界面空间不够时：最大化Wireshark，把上方列表与中间详情之间的分隔线向上拖，把中间与
底部字节之间的分隔线向下拖，让中间区更高。无需把IP 所有子字段展开。仍放不下时可以
截两张补充图，我会择优放入报告。

1. 在CMD 运行ipconfig /all。找到与抓包相同的WLAN 适配器，截图包括标题、物理地址、
IPv4、子网掩码和默认网关，命名为05_地址证据_ipconfig.png。
ipconfig /all

步骤7 修改捕获设置并拍第7 张
1. 确认刚才单播文件已保存，再按Ctrl + K 打开捕获选项。仍选择同一物理联网接口，

ether multicast

步骤8 找广播帧并拍第8 张
1. 在主窗口顶部的显示过滤器输入下列内容，按回车。
eth.dst == ff:ff:ff:ff:ff:ff
2. 单击一条显示出来的记录，优先选择ARP。中间区展开Ethernet II，再展开它下面的
Destination。应看到完整地址ff:ff:ff:ff:ff:ff，以及IG bit 的Group / broadcast/multicast 描
述。
3. 如果是ARP，展开Address Resolution Protocol，保留Opcode、Sender IP、Target IP 可见。
截图同时包括顶部过滤器、列表、Destination 与IG bit，以及底部总数/ Displayed 数，命
名为08_广播帧与IG 位.png。
注意选择的是Ethernet II →Destination →IG bit。LG bit 是另外一个地址管理位；第一字节最
低位才是I/G。只需展示真实界面，不需要手工圈写字段，我会在图注中说明。

没有捕获到背景流量时怎样处理
先确认过滤器写在正确位置，且抓包接口仍是实际联网的物理接口。可重新捕获，延长
到约60 秒；保存为新文件并记录新时长。如果仍没有自然广播，报告可以说明未观察到，
或者按手册使用教师提供的迹线并明确其来源。
如需补一份主动广播样本，可在另一份新抓包中运行ping -4 -n 1 加同网段一个经确认未
